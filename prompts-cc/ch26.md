# ch26｜NVIDIA Build 免費 AI API（讓 Claude Code 寫呼叫範例）

## 這章在講什麼

- 上一章的 Claude API 按用量付費；原書這章改用有免費額度的 NVIDIA Build API，額度足夠個人測試學習。Claude Code 版保留這個主題，由 Claude Code 幫你寫呼叫範例。
- 有了免費額度，就能做平常捨不得做的事：同一個問題讓兩個不同模型同時回答，並排比較；也可以把其中一欄換成 Claude 的回答一起比。
- 並排比較的價值：兩邊說一樣的部分大概可靠，差很多的部分要自己判斷。
- 原書觀察：一個比較簡潔、一個比較完整；翻譯都對但語感不同。結論是沒有哪個模型永遠比較好，要看用途。
- 免費額度適合先試用，但清單上有的模型不一定叫得動；要長期穩定或指定模型，再考慮付費服務。

## 作者做過的實驗／例子

- 原書在試算表放三題，兩欄各由一個模型回覆；驗收項目為有開發者帳號與金鑰、三題兩欄都有回覆、金鑰放在指令碼屬性。
- Claude Code 版：先讓 Claude Code 上網查 NVIDIA Build 目前的呼叫方式，再寫出呼叫範例與比較表；金鑰由使用者自己設定，練習格不碰。

## 演練

### 練習 1：讓 Claude Code 寫「雙模型並排比較」呼叫範例與評分準則

**目的**：不實際呼叫，先讓 Claude Code 依官方說明寫好呼叫範例，並設計一份能真正看出差異的比較實驗。
**送給練習視窗的提示詞**：

```text
請不要問我任何問題，直接完成。這個練習不能使用、讀取或要求任何真實金鑰，全程使用佔位符；不要執行任何呼叫 API 的程式，也不要讀取我的環境變數值。
請在 ch26/雙模型比較設計.md 完成：
1. 官方資訊查詢：用 WebSearch 找 NVIDIA Build（build.nvidia.com）官方說明中 API 呼叫方式的頁面，用 WebFetch 讀取，記下網址、查詢日期（今天日期請自己算）、端點格式、驗證方式、免費額度說明。只寫實際讀到的，讀不到的寫「需自行查證」，不要憑記憶補端點或模型名稱。
2. 為一位虛構的國中英文老師設計三道測試題（一題摘要、一題翻譯、一題開放式建議），說明為什麼這樣選。
3. 並排比較表：欄位為題目、模型 A 回覆、模型 B 回覆、相同處、差異處、我的判斷、採用哪個。模型回覆欄一律寫「待填」，不要自己編造任何模型的答案。
4. 評分準則：準確、簡潔度、語感、是否有想法、長度是否適合用途，各 1 到 5 分並說明給分標準。
5. 呼叫範例（寫在這份 md 裡，不要另建檔案，也不要執行）：一段 Python，依第 1 步查到的格式寫；金鑰從 NVIDIA_API_KEY 環境變數讀取，缺少時清楚報錯；同一題依序呼叫兩個模型，某個模型叫不動或逾時要記錄錯誤並繼續下一個，而不是整支中斷；結果寫成 CSV。另附一段說明：若要改成 Apps Script，金鑰改放指令碼屬性。
6. 一小段「免費額度與付費服務（例如上一章的 Claude API）怎麼選」的決策建議，不要編造數字。
結尾註明：這份範例從未實際執行，端點與模型以查詢日期當天的官方說明為準。
```

**觀察重點**：

- 「模型回覆欄」是否守住「待填」，沒有編造答案？
- 呼叫範例是否真的依官方頁寫，有網址與日期？是否處理某個模型失敗的情況。
- 評分準則是否可操作，另一個人照著打分數能得到接近的結果嗎？

## 教練解說要點

- 並排比較的目的是找出「共識」與「分歧」，分歧處才需要人判斷。
- 讓 Claude Code 寫呼叫範例時，先叫它查官方說明再寫，比憑記憶寫的端點可靠。
- 選型從用途出發；先用免費額度跑通流程，再評估是否值得付費。
