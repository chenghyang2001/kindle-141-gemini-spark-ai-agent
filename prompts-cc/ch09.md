# ch09｜我的 AI 班級秘書

## 這章在講什麼

- 第一個「身分實戰」：老師的班級秘書。用一張三個分頁的班級資料表（學生名單、動態紀錄、出缺席）加技能，把課堂小事變成一句話登記。
- 名單是地基：有了「學生名單」，之後只講姓名，座號、家長稱謂它自己去查；沒有名單它會自己編座號。
- Claude Code 版：資料表用 Google 雲端硬碟連接器建成真的 Google 試算表，親師信用 Gmail 連接器存成真的草稿。
- 親師信只存草稿、絕對不寄出，這是寫進指令的安全鎖；驗收時要去寄件備份確認真的沒寄出。

## 作者做過的實驗／例子

- 原書在 Spark 建 10 位虛構學生名單，包含座號、姓名、家長稱謂、聯絡方式與備註。Claude Code 版改用 8 位虛構學生，建在雲端硬碟「K141-課程練習」資料夾。
- 一次講五件當天的事，逐筆登記並從名單查出座號；再挑兩件健康安全相關的事各寫一封親師信草稿。
- 原書在手機上一句話登記；Claude Code 版可在 Remote Control 或任何一台 PC 的 session 一句話登記，效果一致。

## 演練

### 練習 1：建立名單並一句話登記多件事

**目的**：看「先有名單」如何讓代理人自己查出座號與稱謂，而不是亂編。
**送給練習視窗的提示詞**：

```text
本練習允許使用 Google 雲端硬碟連接器，請遵守安全規則：只建立新檔、不改不刪任何既有檔案；檔名以「課程練習」開頭；放在雲端硬碟資料夾「K141-課程練習」（沒有就建立）。所有學生資料全部虛構，不得使用真實個資。
第一步：虛構 8 位學生的「學生名單」（座號、姓名、家長稱謂、備註）。
第二步：我（虛構）一次講了 4 件今天的事，請你自己擬（例如某人數學進步、某人午休主動幫忙、某人擦傷、某人忘帶水壺），只用姓名，不給座號。
第三步：依名單把這 4 件事登記成「動態紀錄」（日期用今天、座號、姓名、事件類型、內容），座號必須從名單查出來。
第四步：用 Google 雲端硬碟建立 Google 試算表「課程練習-班級資料表」，內容放學生名單與動態紀錄（可用兩段 CSV 轉換或兩份試算表）。
把同樣內容與試算表連結存成 ch09/ex1.md，並附一段反面教材：如果沒有名單，你可能怎麼亂編座號（標明是反面教材）。
最後把建立的檔案（類型、標題、ID）附加寫進 ch09/cleanup.md。
```

**觀察重點**：

- 座號是從名單查出來，還是憑空出現？
- 雲端硬碟裡是否真的出現「課程練習-班級資料表」，且放在指定資料夾？
- `ch09/cleanup.md` 是否記下檔案 ID，方便事後清除？

### 練習 2：從紀錄挑重點寫親師信，只存草稿

**目的**：驗證「安全鎖」寫進指令的效果，並親自到 Gmail 核對。
**送給練習視窗的提示詞**：

```text
本練習允許使用 Gmail 連接器，但只能用 create_draft 建草稿，絕對不可用 send_message 或 reply 寄出任何信。
請讀 ch09/ex1.md 的動態紀錄，挑出兩件「健康或安全」相關的事，為各自的家長寫一封親師信，各建一封 Gmail 草稿：
- 主旨以「課程練習」開頭；收件者一律用虛構地址（例如 parent01@example.com）。
- 資料裡沒有的事不要編造；稱謂依名單的家長稱謂；語氣溫和、說明事實與已做處理，不下診斷。
把兩封信全文與草稿 ID 存成 ch09/ex2.md，最後加「驗收清單」：Gmail 草稿匣應有幾封課程練習信、寄件備份搜「課程練習」應該是 0 封、信中哪些事實要對回原始紀錄。
把建立的草稿（類型、主旨、ID）附加寫進 ch09/cleanup.md。
```

**觀察重點**：

- Gmail 草稿匣是否真的多了兩封「課程練習」草稿，寄件備份是 0 封？
- 信裡有沒有出現紀錄中沒有的細節（例如具體時間、處理方式）？
- 稱謂與姓名是否與名單一致？

## 教練解說要點

- 同一套方法（資料表加技能加安全鎖），套到教師身分；先建名單、再記事件，是系統能運作的基礎。
- 演練全用虛構資料；真實使用時學生個資不要隨意上傳。
- 「只存草稿」寫進提示詞，比事後提醒可靠；但最後還是要自己打開 Gmail 驗一次。
