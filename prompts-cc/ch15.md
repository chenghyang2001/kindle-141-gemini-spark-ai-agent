# ch15｜Claude Code 幫你上網辦事

## 這章在講什麼

- 前面十四章 AI 都在你自己的帳號裡工作（信箱、日曆、雲端硬碟），資料可信度由你負責。本章它要走出去上網。
- Claude Code 版的上網辦事靠 Claude in Chrome（瀏覽器擴充）：它真的會開分頁、讀網頁、把數字寫進文件。這是最讓人驚豔、也最容易被誤用的能力。
- 核心問題：它帶回來的數字，你怎麼知道是對的？網頁有時效、有不同卡片與時段，AI 也可能讀錯位置。
- 流程：先讓它跑一次單一網頁看反應，再做成附網址與擷取時間的文件，最後你自己開同一個網頁核對。
- MCP（模型上下文協定）像 AI 世界的 USB 規格；Claude Code 的 Gmail、日曆、雲端硬碟、Chrome 都是透過 MCP 接上的。接新服務前，先盤點目前實際接了哪些。

## 作者做過的實驗／例子

- 原書請 Spark 抄三個城市的「今日白天」天氣，三個數字全錯，卻附上「完整照抄」的保證。Claude Code 版由控制台用 Claude in Chrome 真的去抄，再由你人工核對。
- 核對的重點不是錯幾個，而是養成「自己開原網頁、找對卡片、抄一次」的習慣。
- 原書以問答遊戲平台的 MCP 當例子；Claude Code 版改成盤點自己這個 session 實際接上的 MCP 連接器。

## 演練

### 練習 1：天氣抄寫任務與核對表

**目的**：先用虛構頁面看懂「自信但出錯」長什麼樣，再把真實上網任務與核對流程設計出來。
**控制台接手**：控制台依 ch15/chrome-task.md 用 Claude in Chrome 開中央氣象署網站，抄三個城市「今日白天」的溫度與降雨機率，連同網址與擷取時間寫進 ch15/chrome-result.md；只讀網頁，不登入、不填表、不點任何送出按鈕。之後由使用者自己開同一網頁填 check-table.md。
**送給練習視窗的提示詞**：

```text
這一題你不要上網，上網的部分由控制台用 Claude in Chrome 接手。請存到 ch15/：
1. fake-weather-page.md：自擬一份虛構「氣象網頁」，三個虛構城市（北城、中城、南城），每個城市有「今日白天」「今晚明晨」「明日白天」三張預報卡，各含溫度範圍與降雨機率，數字彼此不同。
2. fake-report.md：模擬一份「AI 抄寫報告」，故意讓其中兩個城市抄到錯的時段（例如抄成「今晚明晨」），並附一句很有把握的保證。最後一行標註「此為示範錯誤」。
3. chrome-task.md：寫給 Claude in Chrome 的真實任務說明：開中央氣象署網站，查臺北市、臺中市、高雄市「今日白天」的溫度範圍與降雨機率；每筆都要附網址與擷取時間；看不到「今日白天」卡片時寫「未找到」，不可用其他時段代替；只讀，不登入、不填表、不點送出。
4. check-table.md：核對表，欄位：城市、網頁上真正寫的（今日白天）、AI 抄的、一樣嗎；後三欄先留空給我自己開網頁填。
5. 在 check-table.md 最後寫「我該怎麼設計核對流程」至少 4 點，包含核對哪個欄位、哪個時段、抽查幾個、由誰開原網頁。
```

**觀察重點**：

- 錯誤是怎麼被「藏」進虛構報告的？語氣是否很有把握？
- chrome-task.md 有沒有把「時段」與「找不到時怎麼辦」講死？
- 核對流程是否寫明由人開原網頁，而不是叫同一個 AI 再檢查一次？

### 練習 2：盤點已接上的連接器與 MCP 設想

**目的**：理解 MCP 是規格不是產品，並先盤點自己實際接了哪些連接器，再決定要不要接新的。
**送給練習視窗的提示詞**：

```text
請盤點你這個 Claude Code session 目前實際可用的 MCP 連接器，結果存到 ch15/connections.md。安全規則：只看工具清單，不要呼叫任何會寫入、寄出、刪除的工具；如果需要確認連線，只能用唯讀工具（例如列出日曆清單），而且不讀信件內容。
1. 盤點表：列出你看得到的連接器（例如 Gmail、Google 日曆、Google 雲端硬碟、Claude in Chrome 等，以實際看到的為準，不要編造），欄位：名稱、工具名稱前綴（如 mcp__claude_ai_Gmail__）、能做什麼、有哪些「會對外送出或刪除」的工具、我是否真的需要、可否撤銷（到哪裡關）。
2. 標出你建議「保持開啟」與「平常可以關閉」的各幾項，並說明理由。
3. 用 200 字內，向完全沒聽過的人說明 MCP 是什麼、為什麼像 USB。
4. 設想「如果我的專案管理工具提供 MCP 接口」：列出接上後我可以對 Claude Code 說的 3 句話，以及不該讓它做的 2 件事。
```

**觀察重點**：

- 盤點表是不是照實際工具清單寫，而不是憑印象編造？
- 「風險」有沒有區分只讀、會對外送出、會刪除這三種？
- 不該讓它做的事有沒有包含刪除與對外寄送？

## 教練解說要點

- AI 讀網頁會讀錯，而且錯得很有自信；數字進文件前必須人工開原網頁核對。
- 核對不可交給同一個 AI，否則是自己驗自己。
- 接得越多，風險面越大；Claude Code 的連接器可以逐一關掉，先盤點再決定。
