# ch20｜免費資料與 API 大補帖

## 這章在講什麼

- 試算表裡的資料多半是自己輸入的，但天氣、書目等公開資料其實免費可取。本章教你讓 Claude Code 把這些外部資料接進自己的表。
- 作者特別區分：看網頁（轉述網頁內容）和呼叫 API（拿到結構化的數字）是兩回事。Claude Code 版也一樣：用 Claude in Chrome 讀網頁是轉述，寫程式呼叫 API 才是可重複的結構化資料。
- 怎麼挑 API：先看公開 API 清單中「是否需要金鑰」那一欄，初學者優先選不用申請金鑰的。
- 請 Claude Code 寫程式時要交代四件事：資料在哪、回傳長什麼樣、缺資料怎麼辦、格式限制（例如不放金鑰、不加沒要求的功能）。
- 書中列了幾個不用金鑰就能練習的免費 API（天氣、書籍、遊戲角色、圖片類）。

## 作者做過的實驗／例子

- 原書示範一：抓天氣預報寫進試算表；示範二：用書名查書籍資料，缺的欄位填「未提供」而不是留下 undefined。
- 重點：把回傳的 JSON 結構明確貼給 AI，不讓它猜欄位名稱。Claude Code 版由控制台實際打開一個 API 網址，把真實 JSON 和草稿裡自擬的欄位對照。

## 演練

### 練習 1：依情境選 API，寫呼叫草稿並核對真實回傳

**目的**：練習「看金鑰欄位挑 API」與「四件事交代」，做成一份可重複用的選型筆記，再用真實回傳揭穿猜測的欄位。
**控制台接手**：控制台從 ch20/api-選型筆記.md 挑一個標為「需自行查證」的書籍或天氣 API，用 Claude in Chrome 打開它的官方說明頁與一個範例網址（只讀，不登入、不申請金鑰），把真實 JSON 的欄位名稱寫進 ch20/real-response.md，並在選型筆記旁標出哪些欄位猜對、哪些猜錯。
**送給練習視窗的提示詞**：

```text
請自己虛構三個情境（例如：「週末要不要帶傘」「想知道某本書有沒有出版社資料」「班上要做隨機抽籤頭像」），不要問我任何問題。這題你不要連網、不要執行任何程式，上網核對由控制台接手。
請在 ch20/api-選型筆記.md 完成：
1. 一張表，列出 5 個你知道的「不需要申請金鑰」的免費公開 API 類型（只寫名稱與用途，不要編造網址；不確定的標「需自行查證」），標出各適合哪個情境。
2. 對三個情境各寫一段「給 Claude Code 的寫程式提示詞草稿」，必須包含四件事：資料在哪、回傳長什麼樣（自擬一小段 JSON 範例並標「自擬」）、缺資料怎麼辦（填「未提供」，不可出現 undefined）、格式限制（不放金鑰、不加沒要求的功能、輸出寫成 CSV 讓我自己匯入試算表）。
3. 一節「看網頁 vs 呼叫 API」：用一個情境說明兩者拿到的東西差在哪。
4. 最後一節「這份草稿我沒有實際呼叫過」：誠實列出哪些細節（網址、欄位名）需要人工或控制台驗證，並建議控制台先驗哪一個。
```

**觀察重點**：

- 四件事是否每個情境都齊全？「缺資料怎麼辦」有沒有寫成具體字樣？
- 有沒有編造看似真實的網址或欄位？「需自行查證」的標註是否誠實？控制台拿回的真實 JSON 和自擬範例差多少？
- 草稿是否清楚分開「看網頁轉述」與「API 結構化數字」？

## 教練解說要點

- 本章精神：外部資料要「可重複取得」，所以用 API 取代人工複製；挑 API 的第一個濾網是金鑰需求。
- 提示詞的關鍵是把結構給足，AI 就不必猜；猜就容易出錯，真實回傳一對就知道。
- 這個練習只產出草稿加一次核對，實際上線前必須自己小量測試一次。
