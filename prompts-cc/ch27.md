# ch27｜全書總複習：設計一週 Claude Code 工作流

## 這章在講什麼

- 總複習把全書主軸串起來，換成 Claude Code 的工具：常駐規則寫在 CLAUDE.md、重複的事做成 Skills、帳號資料走連接器（Gmail、日曆、雲端硬碟）、定時任務用雲端排程 routines、成品用 Artifact 發布、上網辦事用 Claude in Chrome。
- 不變的原則：代理人要有明確目標與資料來源、權限邊界寫清楚、輸出可檢查、金鑰與授權由人負責、官方資訊要自己查證、持續學習並記錄版本。
- 第 20 到 26 章的資源整理都是同一個概念的不同面向：資源只提供想法，落地責任在使用者。

## 作者做過的實驗／例子

- 全書反覆出現的對照：模糊講法對比把範圍與界線講死的講法；AI 擅長整理、不擅長查證；寫指令和執行指令要分開。
- Claude Code 版的額外對照：能在練習格直接做的（寫檔、Skills、連接器存草稿）與必須由人或控制台把關的（排程、對外發布、上網操作）要分清楚。

## 演練

### 練習 1：為虛構國中老師設計一週 Claude Code 工作流與 Skills 清單

**目的**：整合全書觀念，做出一份可實際落地的週計畫，並檢視每個環節的邊界與風險。
**送給練習視窗的提示詞**：

```text
請不要問我任何問題，直接完成。這個練習只寫設計文件，不要真的操作 Gmail、日曆、雲端硬碟、排程、Artifact 或瀏覽器。
請自行虛構一位國中老師（任教科目、班級數、每週最煩的三件雜事由你設定）。
請在 ch27/一週工作流.md 完成：
1. 週一到週五的工作流表：每天一列，欄位為要自動化的事、用到的 Claude Code 功能（CLAUDE.md、Skill、Gmail／日曆／雲端硬碟連接器、雲端排程 routines、Artifact、Claude in Chrome 擇用）、資料來源、觸發方式、輸出位置與格式、權限邊界（明確寫出不能做的事，例如信件只存草稿不寄出、不刪除非本次建立的東西、不對外發布）、需要人工檢查什麼。
2. 對每個工作流，用七欄位（目標、資料來源、執行步驟、判斷規則、輸出位置與格式、時間或觸發、權限邊界）各寫一段可直接貼給 Claude Code 的指令草稿；檔名、資料夾、學生資料用【佔位符】。
3. 一份這位老師的 CLAUDE.md 草稿（寫在同一份檔案的一節裡，不要另建檔案）：放常駐規則，例如語言、輸出位置、信件只存草稿、學生個資去識別化。
4. 「要做成 Skill 的事」清單：挑 3 件最常重複的事，各寫 Skill 名稱、description（含觸發與不觸發情境）、為什麼值得做成 Skill、最容易出錯的地方。
5. 「風險與把關」一節：至少 5 項，包含幻覺／編造、金鑰外洩、圖片授權、官方功能過時、學生個資，並對每項寫一個具體把關動作（例如功能過時：需要最新資訊時叫 Claude Code 用 WebSearch 查官方文件並記查詢日期）。
6. 三週導入計畫：每週一個重點，先從只寫檔、只存草稿的低風險工作開始，排程與對外發布放最後；附驗收清單。
```

**觀察重點**：

- 每個工作流是否都有明確的權限邊界與人工檢查？排程、發布類工作是否被放在後面導入。
- Skills 清單有沒有對應前面章節的重點，description 是否寫了不觸發情境。
- 學生個資那項有沒有具體做法，例如不貼進對話、去識別化、寫進 CLAUDE.md 常駐規則。

## 教練解說要點

- 好的工作流 = 範圍清楚 + 界線清楚 + 人在迴圈裡檢查；CLAUDE.md 與 Skills 是把這些界線固定下來的地方。
- 工具與功能會變，所以要把「上網查官方文件、記查詢日期」變成習慣。
- 這份計畫是草稿，真正導入前每一步都要小量試跑，先低風險、後高風險。
