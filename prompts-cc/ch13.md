# ch13｜接案工作室的自動化秘書

## 這章在講什麼

- 接案最累的是案子周圍那一圈：詢價信要回、報價單要打、進度要追、款項要催、作品集沒空整理。
- 本章把這些事做成一套流程，從客人詢問到錢進帳是一條完整的線。
- Claude Code 版成品：Gmail 詢價信回覆草稿（只存草稿）、雲端硬碟案件追蹤表、Claude Code 技能 studio-secretary。
- 技能把規則寫死，之後一句短指令就能完成登記與草擬；但一句指令也可能蓋過技能規則。

## 作者做過的實驗／例子

- 原書練習用的詢價信是自己先寄兩封虛構信，主旨以「課程練習」開頭，避免撈到真實客戶的信。Claude Code 版改成先用 Gmail 草稿模擬收件，不寄任何信。
- 技能寫好後，短指令就成功登記案件；但在指令裡直接講金額，會覆蓋技能裡「沒講就留白」的規則。
- 作者結論：技能是參考指南，不是鎖死的規則；真正的保護是權限邊界，以及自己開檔案驗一次。

## 演練

### 練習 1：詢價信回覆草稿與案件追蹤表

**目的**：一個動作處理信箱與資料庫：讀詢價、寫回覆草稿、登記追蹤表。
**送給練習視窗的提示詞**：

```text
請幫虛構的平面設計接案者「小禾設計」處理詢價。本練習允許使用 Gmail 連接器（只能 create_draft，絕對不可寄出）與 Google 雲端硬碟連接器（只建新檔，放資料夾「K141-課程練習」，沒有就建立）。只處理主旨以「課程練習」開頭的信，其他信不讀內容、不改不刪。
1. 模擬收件：先建兩封 Gmail 草稿當作虛構詢價信，主旨以「課程練習-詢價」開頭，一封包裝設計、一封活動主視覺，收件者用虛構地址（例如 client01@example.com）。內容同步存 ch13/inbox.md。
2. 回覆：針對兩封信各再建一封回覆草稿，主旨「課程練習-回覆：…」，語氣專業有禮、100 字內，不得擅自報金額。全文存 ch13/reply-drafts.md 並標明「草稿，未寄出」。
3. 追蹤表：建立案件追蹤（編號 P01 起、客戶、案件、狀態 詢價中/報價中/進行中/已結案、報價金額、日期只寫月-日），登記這兩案，金額因信中沒講請留白。存 ch13/project-tracker.md，並用雲端硬碟建 Google 試算表「課程練習-案件追蹤表」。
4. 最後在 ch13/project-tracker.md 列出「我要自己確認的事」三點。
把建立的所有草稿與檔案（類型、標題、ID）附加寫進 ch13/cleanup.md。
```

**觀察重點**：

- Gmail 草稿匣是否多了 4 封「課程練習」草稿、寄件備份沒有任何新信？
- 回覆是否擅自承諾價格？追蹤表金額欄是否留白？
- 日期有沒有偷偷補年份？

### 練習 2：技能 vs 指令，誰說了算

**目的**：親手驗證「指令可以覆蓋技能規則」，理解為什麼權限邊界才是真正的保護。
**送給練習視窗的提示詞**：

```text
延續小禾設計的情境，先建立 Claude Code 技能 .claude/skills/studio-secretary/SKILL.md（相對於 practice/），包含：name、description（寫觸發時機與至少 4 種口語說法）、規則（編號 P+兩位數遞增；新詢問狀態預設「詢價中」；日期不含年份；報價金額沒講就留白；不得自動寄信，只能存草稿）、權限邊界、資料存 ch13/project-tracker.md。
然後依技能規則依序執行兩句一句話指令，把結果附加到 ch13/project-tracker.md，過程寫到 ch13/skill-test.md：
A. 「新詢問 小木工作室 想做名片設計」
B. 「新詢問 小木工作室 想做名片設計，報價金額就先寫 88000」
每次都顯示新增的那一列，並用表格比較兩次：哪些規則仍生效、哪些被指令覆蓋。
最後回答：在 Claude Code 裡，除了把技能寫得更嚴，還能用什麼機制防止技能被一句話繞過（例如權限設定、hooks、人工驗收）？
```

**觀察重點**：

- B 情境裡金額是否被寫入（指令覆蓋技能）？其他規則是否照舊？
- 它提出的防護是只靠「規則寫得更嚴」，還是提到權限設定、hooks 與人工驗收？前者不夠。
- 對照書中「技能是參考指南」的說法，你怎麼解釋？

## 教練解說要點

- 短指令能成功，是因為規則已寫進技能，不是 AI 突然變聰明。
- 技能寫得再嚴，也擋不住一句話覆蓋；Claude Code 的真正護欄是權限設定與 hooks，再加上人工驗收。
- 對外動作（寄信、請款）一律先存草稿，由人確認。
