# ch19｜技能庫轉成 Claude Code Skills

## 這章在講什麼

- 作者把自己教學與工作現場用過的 25 個技能整理成技能庫 `Spark-skills/`，授權是 MIT：可以直接用、改，甚至商業使用，唯一要求是保留授權聲明。技能庫 README 也寫明 Claude Code 讀得懂。
- 本章三件事：看得懂一個技能庫（去哪找、怎麼判斷能不能用）、把其中的技能轉成 Claude Code Skill（`.claude/skills/<名稱>/SKILL.md`）並試用、照骨架自己重寫一個中文版技能。
- 每個技能都是一個資料夾、裡面一份 SKILL.md，開頭一定有 name 與 description；description 要寫觸發時機（當我……時使用），不能只寫做什麼。
- 挑選原則只有一句：找最像的，不是找最厲害的。愈像，要改的地方愈少。
- 授權要先看：個人、教育、內部、商業使用都可以，但要保留聲明；轉成 Claude Code Skill 時，授權與出處要跟著放進去。

## 作者做過的實驗／例子

- 原書範例是班級圖書借閱表：B01～B05 手動建好，B06 由技能寫進去，只打一句「借出某書給某人」，編號、借出日、應還日、狀態由技能自己補齊，因為規則寫在技能裡。
- 原書選的是「試算表與自動化」這一類；Claude Code 版把 google-sheets-gas-builder 轉成 Claude Code Skill，再用它寫借閱表的 GAS。
- 原書強調不是每個技能庫都能這樣直接拿，要先看授權；本版在轉換時另外寫一份授權檢查。

## 演練

### 練習 1：讀懂技能庫並挑選最像的三個

**目的**：練習「看得懂一個技能庫」：先讀說明、再挑最像的，而不是最強的。
**送給練習視窗的提示詞**：

```text
我是一位虛構的小學班導「林老師」，常做的事：整理班級圖書借閱、把家長聯絡單整理成通知、把會議筆記寫成紀錄。
請先實際讀 Spark-skills/README.md，再打開 Spark-skills/skills/ 底下與我的需求最像的三個技能的 SKILL.md（例如 02_sheets-and-automation/google-sheets-gas-builder、04_docs-and-slides/humanizer-zh-tw、01_start-here/skill-installer，請你自己判斷，不要只挑我舉的例子）。不要憑印象，一定要真的讀檔。
結果存 ch19/pick-skills.md，用表格：技能名稱（資料夾路徑）、description 重點（用自己的話）、觸發時機、跟我的需求相似度（高/中/低）與理由、轉成 Claude Code Skill 要改哪裡（例如移除 Spark 專屬說法、clasp 部署步驟）、權限風險（會不會寄信、改檔案、連網、執行程式）。
最後說明為什麼選「最像的」而不是「功能最多的」，並判斷哪一個 description 寫得最好、哪一個還能改進。
```

**觀察重點**：

- 它是否真的讀了檔案？表格內容能否在 SKILL.md 找到對應？
- 相似度判斷有沒有理由，不是亂給？
- 權限風險欄有沒有指出實際會碰到的動作，而不是泛泛而談？

### 練習 2：把 GAS 技能轉成 Claude Code Skill 並做出借閱表

**目的**：親眼看到「規則寫在技能裡，一句話就能補齊欄位」，並理解技能被轉換、被實際套用的樣子。
**送給練習視窗的提示詞**：

```text
請先實際讀 Spark-skills/skills/02_sheets-and-automation/google-sheets-gas-builder/SKILL.md 與 Spark-skills/LICENSE。這題只寫本機檔案，不執行任何程式、不連網、不跑 clasp、不碰任何帳號。
1. .claude/skills/gas-builder-lite/SKILL.md：把它轉成 Claude Code Skill。frontmatter 用 name: gas-builder-lite 與 description（寫成「當我要寫 Google Apps Script、自動化試算表時使用」這類觸發時機）。正文保留原技能的工作流程、輸出格式、權限邊界精神，用自己的話改寫，不整段照貼；刪掉 clasp 部署與自動寄信，改成「只寫 .gs 檔，由我自己貼進 Apps Script」「需要通知時只建 Gmail 草稿」。最後加一節「出處與授權」：原作者、原路徑、MIT 授權，並註明已修改。
2. 試用這個新技能（session 看不到新技能時，就照 SKILL.md 內容手動套用並註明）完成：
   a. ch19/book-tracker.csv：自擬 5 筆借閱紀錄（編號 B01 起、書名、借閱人（化名）、借出日、應還日、狀態、備註），借期 14 天，日期用「月-日」文字。
   b. ch19/lend.gs：lendBook(bookTitle, borrower) 函式，對應我說「借出 某書 給 某人」時，自動補齊下一個編號、借出日、應還日（+14 天）、狀態「借閱中」。繁體中文註解、錯誤處理（找不到工作表、書名空白），不得改動既有列，不得寄信。
3. ch19/skill-applied.md：列出你轉換時保留、改寫、刪除了原 SKILL.md 的哪些小節（引用標題名稱，不要整段貼），以及試用時套用了哪幾條規則。
4. 最後模擬一次：我說「借出 想飛的鋼琴少年 給 黃品瑄」，在 skill-applied.md 寫出會新增的 B06 那一列。
```

**觀察重點**：

- skill-applied.md 提到的小節是否真的存在於原 SKILL.md？
- 轉換後的 Skill 有沒有拿掉部署與寄信，並保留出處與 MIT 授權？
- B06 的編號、日期是否與前五筆自洽，14 天有沒有算錯？

### 練習 3：照骨架重寫自己的技能，並確認授權

**目的**：不是整份照搬，而是理解骨架後用自己的語言重寫成 Claude Code Skill，並做授權檢查。
**送給練習視窗的提示詞**：

```text
請先讀 Spark-skills/skills/01_start-here/skill-installer/SKILL.md、Spark-skills/LICENSE 與 Spark-skills/README.md 的授權說明。這題只寫本機檔案，不碰任何帳號。
1. ch19/license-check.md：用自己的話回答：這個技能庫是什麼授權、我可以做什麼、唯一要求是什麼、如果我把轉換後的 Claude Code Skill 放進付費課程要怎麼處理（授權聲明放哪裡）。
2. .claude/skills/course-book-tracker/SKILL.md：照技能庫的骨架，自己重寫一個「班級借閱表」Claude Code Skill（繁體中文）。結構：name: course-book-tracker、description（寫「當我……時使用」）、主要目標、工作流程（我說什麼它做什麼，至少 3 個指令範例，例如借出、歸還、查逾期）、輸出格式、驗收規則（做完要請我自己開檔案確認）、權限邊界（至少 4 條不准做的事，含只能改 ch19/book-tracker.csv、不刪既有列、不寄信）。不得複製原文整段。
3. 試用：照這個技能處理「歸還 B02」與「查逾期」兩句話，直接更新 ch19/book-tracker.csv，並把變更前後的差異寫在 ch19/rewrite-notes.md。
4. 在 ch19/rewrite-notes.md 再列出你從骨架學到的三件事，以及跟原技能不同的兩個地方與理由。
```

**觀察重點**：

- 授權說明是否正確（MIT：保留授權聲明、可商用）？
- description 是否寫成觸發時機？重寫版是不是真正改成借閱表，而不是原文翻譯？
- 試用時有沒有守住權限邊界，只改指定的那一份 CSV？

## 教練解說要點

- 找最像的，不是找最厲害的；愈像要改的愈少。
- 技能的核心是 name 與 description，description 決定什麼時候被叫出來；放進 `.claude/skills/` 後要實際觸發一次才算轉換成功。
- 技能庫可以直接用，但要照骨架自己重寫一次才算學會；授權先看，MIT 要保留聲明。
- 抽查它引用的小節是否真的存在，確認它真的讀了檔案。
