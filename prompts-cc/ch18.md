# ch18｜Claude Code 指令與技能生成器

## 這章在講什麼

- 原書介紹網站上的三個小工具，把「想做的事」轉成 AI 看得懂的格式。Claude Code 版直接請 Claude Code 當這三個工具；它不是取代思考，而是把想法排成格式。
- 工具一「指令生成器」：填七個欄位（目標、資料來源、執行步驟、判斷規則、輸出位置與格式、時間或觸發、權限邊界），組出完整任務提示詞。權限邊界最重要：要寫清楚它不可以做什麼。
- 工具二「技能生成器」：產出 Claude Code Skill，也就是 `.claude/skills/<名稱>/SKILL.md`，開頭 frontmatter 有 name 與 description，正文拆成五小塊，後三塊（格式規定、驗收規則、權限邊界）可改但不要刪。
- 技能名稱只收小寫英文、數字與連字號，長度 1～64；本課再加兩條好習慣：不連續連字號、不以連字號開頭或結尾。
- 工具三「技能轉化器」：把別的 AI 的設定（GPTs 指示、Gemini Gem、Spark 技能或純文字）轉成 Claude Code Skill。

## 作者做過的實驗／例子

- 原書範例想法是「整理會議紀錄」，用七欄位填完後即時組成結構清楚的指令；本版請 Claude Code 照七欄位產出可直接貼給它自己的提示詞。
- 原書的名稱欄會擋你，不是工具龜毛，而是平台本來的規定；Claude Code 的 skill 名稱規則幾乎一樣。
- 原書提醒輸入內容會被送到哪裡；Claude Code 版的 skill 寫在本機專案資料夾，可以實際觸發測試。

## 演練

### 練習 1：用七欄位生成一份任務提示詞

**目的**：體驗把一句模糊的想法拆成七件事後，提示詞變得多完整。
**送給練習視窗的提示詞**：

```text
請當「指令生成器」。我的一句話想法是：「幫我整理這週的會議紀錄」。資料請自擬，不要問我。這題只寫本機檔案，不讀信、不碰任何雲端帳號。存到 ch18/：
1. command-form.md：填七個欄位：目標、資料來源（寫清楚可讀什麼、不要讀什麼，例如只讀雲端硬碟「K141-課程練習」資料夾中標題以「課程練習」開頭的會議筆記）、執行步驟（至少 4 步）、判斷規則（含：遇到不確定的負責人怎麼處理）、輸出位置與格式、時間或觸發、權限邊界（至少 3 條不可做的事，例如不寄信、不刪檔）。
2. command.md：把上面組成一段可直接貼給 Claude Code 的完整任務提示詞，200 到 300 字，用條列。
3. compare.md：對照「原本的一句話」與「完整提示詞」，列出三個可能出錯的地方，說明七欄位如何降低風險。
```

**觀察重點**：

- 權限邊界寫的是「不准做什麼」，還是只重複目標？
- 判斷規則有沒有把不確定時的處理方式講死？
- 完整提示詞是否能不看表單就獨立被理解？

### 練習 2：技能生成、命名檢查與技能轉化

**目的**：寫出一個真的能被 Claude Code 觸發的 Skill，並練習把別人的設定轉成 Claude Code 格式。
**送給練習視窗的提示詞**：

```text
請當「技能生成器」與「技能轉化器」。這題只寫本機檔案，不碰任何帳號。
1. ch18/name-check.md：列 8 個技能名稱，4 個合法（如 class-secretary）、4 個不合法（含大寫、底線、中文、連續連字號、以連字號開頭或結尾），逐一判斷並說明原因。規則：只能小寫英文、數字、連字號，長度 1 到 64，不可連續連字號、不可以連字號開頭或結尾。
2. .claude/skills/meeting-helper/SKILL.md：產出一個 Claude Code Skill。開頭用 --- 包起來的 name: meeting-helper 與 description（要寫成「當我……時使用」的觸發時機）；正文拆成五塊：資料放哪裡、我說某句話時要做什麼、格式規定、驗收規則、權限邊界（至少含：不寄信、不刪檔、只輸出到 ch18/）。
3. 試用：自擬一段 8 行的虛構會議筆記，照 meeting-helper 技能處理，結果存 ch18/skill-trial.md，並在最上方註明技能有沒有被你辨識成可用技能；若目前 session 還看不到新技能，就照 SKILL.md 內容手動套用並註明「需重開 session 才會自動載入」。
4. ch18/convert-demo.md：自擬一段「ChatGPT GPTs 的指示欄」文字（約 100 字，英文寫作潤飾助手），轉成 Claude Code Skill 格式（name、description、五塊結構），並列出轉換時補了什麼、刪了什麼。
```

**觀察重點**：

- 名稱檢查是否逐條說明違規原因？
- description 寫的是觸發時機還是功能描述？試用時它有沒有真的照 SKILL.md 的格式與權限邊界做？
- 轉換過程有沒有補上權限邊界？別人的設定常常沒有這一塊。

## 教練解說要點

- 好提示詞的關鍵是把「不准做的事」寫清楚，而不是把目標寫得更漂亮。
- 技能的結構（名稱、說明、正文）在 Spark、Claude Code、Codex 之間幾乎通用，所以可以轉換。
- 轉換別人的設定時，最容易漏掉的是權限邊界與驗收規則；寫完一定要實際觸發一次。
