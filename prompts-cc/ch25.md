# ch25｜AI 模型 API 資源（Claude API 版）

## 這章在講什麼

- 原書教試算表或 Apps Script 呼叫其他 AI 模型的 API；Claude Code 版改成讓 Claude Code 幫你寫呼叫 Anthropic Claude API（Messages API）的程式，把 Claude 接進自己的工作流。
- 使用 API 需要金鑰，且按用量計費，和 Claude Pro／Max 訂閱是分開的。原書示範的整合式服務概念仍可參考，但這章以 Anthropic 官方 API 為主。
- 踩坑觀念保留：開啟延伸思考（extended thinking）時，思考內容也吃 token；max_tokens 設太小，回傳的 stop_reason 會是 max_tokens 而不是 end_turn，回答被截斷或是空的，調大上限即可。
- 中文通常比英文耗 token，給中文任務時上限要開大一點。
- 金鑰的正確放法：環境變數或 Apps Script 的指令碼屬性，絕對不要寫進程式碼、不要貼進對話。

## 作者做過的實驗／例子

- 原書實測某模型光推理就用掉 800 多個 token，上限設 800 時完全輪不到答案。
- 原書示範把金鑰存進指令碼屬性，程式只讀取名稱；Claude Code 版同樣寫成從 ANTHROPIC_API_KEY 環境變數或指令碼屬性讀取。

## 演練

### 練習 1：依情境挑 Claude 模型，寫呼叫草稿與金鑰安全檢查表

**目的**：不碰任何真金鑰，練習「選型、寫草稿、排錯、守住金鑰」四件事，模型與參數以官方文件為準。
**送給練習視窗的提示詞**：

```text
請不要問我任何問題，直接完成。這個練習不能使用、讀取或要求任何真實金鑰，全程使用佔位符【YOUR_KEY】；不要執行任何呼叫 API 的程式，也不要讀取我的環境變數值。
請在 ch25/api-規劃.md 完成：
1. 官方資訊查詢：用 WebSearch 找 Anthropic 官方 Claude API 文件中「模型總覽」「Messages API」「延伸思考」的頁面，用 WebFetch 讀取。記下網址與查詢日期（今天日期請自己算）。模型名稱、價格、參數名稱只能寫你在官方頁實際讀到的，讀不到的寫「需自行查證」，不要憑記憶補。
2. 虛構三個老師情境（例如：批改短文給回饋、把家長通知翻成英文、把一週課表整理成表格），為每個情境寫選模型的考量（成本、速度、是否需要延伸思考、中文品質），引用第 1 步查到的資訊。
3. 一份 Apps Script 風格的程式碼草稿（寫在這份 md 裡，不要另建檔案，也不要執行）：金鑰從指令碼屬性讀取、依官方文件設定必要的標頭與 max_tokens、檢查回傳的 stop_reason、錯誤時輸出可讀訊息。另附一小段 Python 版，金鑰從 ANTHROPIC_API_KEY 環境變數讀取、缺少時清楚報錯。兩份程式裡都不可出現任何金鑰字串。
4. 「排錯速查」：回傳內容是空的或被截斷、stop_reason 是 max_tokens 時，原因是什麼（含延伸思考也吃 token）、怎麼處理、為什麼中文要把上限開大。
5. 「金鑰安全檢查表」6 條勾選項，至少包含不貼進對話、不放進共用文件或 git、外洩時到官方主控台撤銷。
結尾註明：這份草稿從未實際執行，端點、參數與模型名稱以查詢日期當天的官方文件為準。
```

**觀察重點**：

- 程式碼草稿裡有沒有硬寫金鑰？Python 版缺金鑰時是否明確報錯，而不是靜默帶空字串。
- 模型名稱與參數是否都對得上官方頁？有沒有「需自行查證」或查詢日期。
- 排錯那節是否準確解釋「思考也吃額度」與 stop_reason 的差別。

## 教練解說要點

- 金鑰等於密碼：放環境變數或指令碼屬性、不寫進程式、不外流，是本章最重要的規矩。
- 內容為空不一定是壞掉，先看 stop_reason 再調上限。
- 模型清單與價格會變，叫 Claude Code 上網查官方文件並記日期，比背答案可靠。
