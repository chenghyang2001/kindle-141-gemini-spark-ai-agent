# ch03｜行事曆與待辦自己排：用日曆連接器先提案再建立

## 這章在講什麼

- 本章讓 Claude Code 透過 Google 日曆連接器真的建立、刪除活動。原書先建專用練習日曆；Claude Code 版的連接器不能建新日曆，改成所有活動標題一律以「課程練習」開頭，事後好找好刪。
- 流程：先把 10 筆虛構日程排成計畫、抓衝突，再逐筆建立；Claude Code 的工具權限確認框就對應原書的「發送／跳過」確認視窗。
- 重點觀察：不同動作的保護程度不同（建立、刪除都該確認），說明書不一定寫清楚，只能自己實測。
- 換到真實工作時照同樣順序：先用可辨識的練習資料跑完整套流程，確認每步行為和預期相同，再換真資料。

## 作者做過的實驗／例子

- 原書：10 筆日程分成活動與待辦，建立時逐筆跳出確認框。Claude Code 版：每次 `create_event` 都會經過權限確認，並且先在檔案裡列出「準備建立」清單。
- 原書：刪除待辦時，待辦從 5 筆變 4 筆，被刪的正是指定那一筆。Claude Code 版：連接器沒有待辦清單，改用「課程練習｜待辦：」全天活動代替，刪除前後各列一次核對。
- 若它沒問就直接刪，作者建議以畫面實際看到的為準，並更小心。

## 演練

### 練習 1：把一堆行程排成計畫，只建立確認過的

**目的**：練習讓 Claude Code 先「提案、等確認」，再真的寫入日曆。
**送給練習視窗的提示詞**：

```text
這是課程練習，會用到我的真實 Google 日曆，請遵守安全規則：
- 活動標題一律以「課程練習｜」開頭，只寫入我的主要日曆。
- 不可邀請任何人（不加 attendees），不可修改或刪除任何既有活動。
步驟：
1. 先算出今天日期，自行虛構「下週一到週五」一位學校行政人員的 10 筆行程（日期、起訖時間、地點、備註，註明虛構），其中故意放兩筆時間互相衝突。
2. 依日期整理成表格，找出衝突並提出調整建議，列在「待我確認」區，先不要建立衝突的那兩筆。
3. 寫出「準備建立」清單：每筆一行「標題／時間／日曆」。
4. 只把清單中前 3 筆不衝突的行程用 create_event 建立，每筆分開呼叫（讓我能逐筆確認或拒絕）。
5. 用 list_events 查下週，回報實際建立了幾筆「課程練習｜」活動。
全部寫進 ch03/ex1-calendar-plan.md，並把建立的活動（類型、標題、事件 ID）附加寫進 ch03/cleanup.md。
```

**觀察重點**：

- 兩筆衝突有沒有被抓出來？是「建議」還是「擅自修改」？
- 是否逐筆呼叫 `create_event`，讓你有機會一筆一筆確認？
- 日曆上是否正好 3 筆、沒有邀請任何人、沒有多出你沒給的行程？

### 練習 2：刪除之前先確認那一筆

**目的**：把「刪除」這種不可逆動作設計成必須明確確認的流程。
**送給練習視窗的提示詞**：

```text
這是課程練習，會用到我的真實 Google 日曆。只可刪除本練習剛建立的活動，絕不可刪除或修改其他任何活動。
1. 用 create_event 建 5 筆全天活動當作待辦，標題「課程練習｜待辦：…」，日期分別是昨天、明天、後天、下週二、下週四（內容虛構）。
2. 用 list_events 列出這 5 筆，存成 ch03/ex2-tasks.md 的「刪除前」區塊（含事件 ID）。
3. 任務：「刪掉過期的那一筆待辦」。先寫出你判斷哪一筆過期及依據；若有兩筆以上都算過期，停下來列出，不要自己選。
4. 寫出確認框文字：「確定要刪除『…』（事件 ID …）嗎？」附「跳過／確認」。
5. 確認標題與 ID 都對上之後，才用 delete_event 只刪那一筆，再 list_events 一次寫成「刪除後」區塊，核對是否剩 4 筆。
6. 加一段說明：對建立、對刪除該用什麼不同程度的確認。
最後把仍留在日曆上的 4 筆（類型、標題、事件 ID）附加寫進 ch03/cleanup.md。
```

**觀察重點**：

- 剩下的筆數是否為 5 減 1？被刪的是否正是昨天那一筆？
- 刪除前有沒有用標題＋事件 ID 雙重核對，而不是只憑標題？
- 對照書中「不同動作保護不同」：你會想把哪些動作都加上確認？

## 教練解說要點

- 日曆章的真正教學是方法論：用「課程練習」前綴隔離、用可辨識的假資料跑完整流程、逐步驗證行為。
- 權限確認框是最後防線，但要讓它有機會出現：一筆一筆呼叫，不要一次全做。
- 提醒觀眾：練完到 Google 日曆搜「課程練習」親眼核對，並依 ch03/cleanup.md 清掉。
