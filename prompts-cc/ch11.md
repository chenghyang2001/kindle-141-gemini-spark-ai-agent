# ch11｜上班族的個人工作流

## 這章在講什麼

- 第三個身分實戰：上班族的個人工作流，涵蓋收信分類、出差規劃、發票報帳、月底統計、每月排程提醒，最後整套存成技能 expense-helper。
- 本章最重要的一件事：AI 算數很可靠，但認字不可靠。實測金額、發票號碼、小計都對，店家名稱和品項卻讀錯過。
- 報帳資料：數字可以信，文字欄位一定自己核對；正因數字全對，文字錯誤特別容易看漏。
- 指令三重點：讀不出來要留白不要猜；禁止編造具體資訊（班次、旅館、訂位代號等）；寄信只存草稿並到寄件備份驗證。
- Claude Code 版的「每月排程」用 claude.ai 雲端排程（routines），由控制台建立、驗收後刪除。

## 作者做過的實驗／例子

- 原書的報帳明細有三種來源：事先建好的六筆、拍發票圖讀出的三筆、手機一句話登記的一筆，格式一致，因為規則寫在技能裡。
- 月報摘要五個類別小計全部正確；讀發票圖時金額與發票號碼全對，店家和品項各錯一處（字形相近的詞被換掉）。
- Claude Code 版：Claude Code 也能讀圖片，演練先用文字模擬模糊發票；技能寫在 `.claude/skills/expense-helper/`。

## 演練

### 練習 1：模擬讀發票，檢查「留白而不是猜」

**目的**：體驗「算數可靠、認字不可靠」，並練習把防猜規則寫進指令。
**送給練習視窗的提示詞**：

```text
請做一個發票報帳模擬，資料全部虛構，結果存成 ch11/ex1.md：
第一步：虛構 4 張發票的「文字內容」，刻意讓其中兩張有模糊字（用 [?] 標示看不清的部分，例如店家名稱缺一個字、品項被遮住一半）。
第二步：寫出你的「讀發票規則」，要包含這三句：讀不出來就先留白並告訴我是哪一張、不要自己編；不要編造店家、品項、發票號碼；只存草稿、不寄信。
第三步：依規則把 4 張發票登記成報帳明細表（編號、日期、店家、品項、類別、金額、發票號碼、狀態），模糊欄位留白並標示原因；同時存一份 ch11/expenses.csv。
第四步：算出各類別小計與總計，列出計算過程。
最後附一段：如果沒有那三句防猜規則，你認為最可能出錯的是哪個欄位？為什麼？
```

**觀察重點**：

- 模糊欄位有沒有留白，而不是被填上一個看似合理的字？
- 金額小計能不能用自己算的結果核對？
- 對照書中結論：數字可信、文字欄位自己核對。

### 練習 2：月底統計、技能與每月提醒排程

**目的**：把統計、待處理清單與排程結合，並練習設計安全的排程（驗收後刪除）。
**控制台接手**：控制台用 `/schedule` 依 `ch11/routine-spec.md` 建立「課程練習_每月報帳檢查」雲端排程、手動觸發一次確認輸出，然後刪除並記入 `ch11/cleanup.md`。
**送給練習視窗的提示詞**：

```text
接續上一個練習，請讀 ch11/ex1.md 與 ch11/expenses.csv，做三件事：
1. 存 ch11/ex2.md：「月報摘要」表格（各類別筆數與金額小計），另列「待處理清單」（所有留白或標待確認的項目）。
2. 建立 Claude Code 技能 .claude/skills/expense-helper/SKILL.md（相對於 practice/）：frontmatter 的 description 含至少 5 種口語說法；正文 6 條以上規則，包含留白不猜、不編造、不寄信、資料存 ch11/expenses.csv。
3. 存 ch11/routine-spec.md：給控制台用的雲端排程設定單，包含排程名稱「課程練習_每月報帳檢查」、每月固定日期時間（cron 寫法）、要用的連接器、完整提示詞（權限邊界寫明唯讀與不寄信、結果只建 Gmail 草稿且主旨以「課程練習」開頭、輸出留時間戳）、驗收步驟、驗收後要刪除排程。練習格不要自己建立排程。
最後在 ch11/ex2.md 挑出 2 個我在真實使用前一定要手動核對的欄位，並說明原因。
```

**觀察重點**：

- 待處理清單是否精準對應到留白的欄位？
- 排程設定單是否遵守「唯讀、固定位置、時間戳、驗收後刪除」？
- 控制台建立的排程跑完後，是否只產生「課程練習」草稿、沒有寄出任何信？

## 教練解說要點

- 最重要的一句話：算數可靠、認字不可靠；報帳要把數字與文字分開看待。
- 「留白不要猜」與「不准編造」是互補的兩道防線：前者處理讀不清，後者處理想補資訊。
- 排程是無人值守的動作，權限邊界要比平常更嚴；練習完一定刪掉。
