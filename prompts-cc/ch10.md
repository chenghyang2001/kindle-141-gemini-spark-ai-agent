# ch10｜每天早上的經營簡報與會議秘書

## 這章在講什麼

- 第二個身分實戰：小公司老闆的經營簡報與會議秘書。核心是一張「行動項目追蹤表」，它是整套系統的地基。
- 會議紀錄跑完後，新的行動項目接到追蹤表；晨報、週報、待辦都從這張表產出。
- 原書發現 Spark 不能建分頁或日曆，要「容器自己建，內容交給它」；Claude Code 可以用雲端硬碟連接器建試算表、用日曆連接器讀行程，容器也能自己建。
- 共通發現：AI 會自己補上你沒給的資訊（例如憑空加一個年份）。數字、日期、金額一定要自己核對。
- 最後把規則存成技能，用一句話改狀態並固定回報作業結果。

## 作者做過的實驗／例子

- 原書預先建好 8 筆行動項目的追蹤表（編號、行動項目、負責人、期限、狀態），貼上三場會議紀錄，新項目接在最後面。
- 每日經營晨報：今日三件最重要的事、今日行程、待辦事項，三個來源合成一頁。Claude Code 版的「今日行程」改用 Google 日曆連接器唯讀查詢。
- 一句話驗收：把某編號狀態改成已完成，回報還剩幾件，同時回報寫入列數、異動分頁、待辦筆數、郵件狀態。

## 演練

### 練習 1：會議紀錄變成行動項目，晨報自己長出來

**目的**：看追蹤表如何成為系統地基，並練習檢查有沒有被偷補資訊。
**送給練習視窗的提示詞**：

```text
本練習允許使用 Google 雲端硬碟連接器（只建新檔）與 Google 日曆連接器（只讀，不建立、不修改任何事件）。檔名以「課程練習」開頭，放在雲端硬碟資料夾「K141-課程練習」（沒有就建立）。公司與人名全部虛構。
第一步：虛構「行動項目」追蹤表 6 列（編號 A01–A06、行動項目、負責人、期限、狀態）。
第二步：虛構一段約 150 字的會議紀錄，裡面有 3 件新待辦，其中 1 件故意沒講負責人、1 件故意沒講期限。
第三步：把新行動項目接到追蹤表最後面（A07 起），沒講的欄位標「待確認」，不要自己編。存成本機 ch10/tracker.csv，並用雲端硬碟建立 Google 試算表「課程練習-行動項目追蹤表」。
第四步：用日曆連接器查我今天的行程（只列時間與標題），加上追蹤表，產出「每日經營晨報」：今日最重要三件事、今日行程、本週期限內的項目、尚未有負責人的項目。
全部存成 ch10/ex1.md（附試算表連結），最後加「自我稽核」：晨報每個數字與日期是否都找得到來源？有沒有你自己補上的內容？
把建立的檔案（類型、標題、ID）附加寫進 ch10/cleanup.md。
```

**觀察重點**：

- 沒講負責人與期限的項目有沒有被標「待確認」，還是被順手補上了？
- 晨報的「今日行程」是否真的來自你的日曆，而且沒有新增或改動任何事件？
- 「自我稽核」是否誠實？對照書中「它會自己補上沒給的資訊」。

### 練習 2：寫成技能，一句話改狀態並回報作業結果

**目的**：練習「作業回報」格式，讓代理人每次動作後主動說清楚做了什麼。
**送給練習視窗的提示詞**：

```text
接續上一個練習，請做下面的事：
1. 建立 Claude Code 技能 .claude/skills/meeting-secretary/SKILL.md（相對於 practice/）：frontmatter 有 name 與 description（含至少 4 種口語說法），正文 5 條規則，其中一條要求「每次動作後固定回報四件事：寫入列數、異動檔案、待辦筆數、郵件狀態（本技能不寄信）」，並寫明資料來源是 ch10/tracker.csv。
2. 依技能規則執行「把 A03 的狀態改成已完成，然後告訴我還有幾件沒完成」：更新 ch10/tracker.csv，給出作業回報。
3. 再執行「把 A99 改成已完成」（這個編號不存在），示範正確回應，不要假裝成功、不要新增一筆。
把過程與回報存成 ch10/ex2.md，最後用一段話說明：為什麼要固定要求作業回報？
```

**觀察重點**：

- 作業回報的四項是否都在、數字對得上 `tracker.csv`？
- 面對不存在的編號，是回報找不到，還是亂編一筆？
- 這就是用回報格式取代「相信它說好了」。

## 教練解說要點

- 本章精華：一張追蹤表當地基，會議、晨報、待辦都從它長出來。
- Spark 要你自己建容器；Claude Code 能自己建，但權限要在提示詞裡講清楚（只建新檔、日曆只讀）。
- 「它會幫你補資訊」的風險不分工具，數字、日期、金額一定自己核對。
