# ch08｜把調好的提示詞，變成拿得走的技能

## 這章在講什麼

- 調了好幾個晚上的提示詞，如果鎖在某個平台（原書是 Gem）裡，換工具就要重寫、改了什麼也沒紀錄。
- 搬成標準格式的 `SKILL.md` 之後，提示詞變成自己保管的純文字檔，可以放進 git、跨工具使用。
- Claude Code 版流程：把提示詞整理成 `.claude/skills/<名稱>/SKILL.md`（一個提示詞一個資料夾），之後用 `/<名稱>` 呼叫或讓它自動出場。
- 搬過來的不只是名字，連整套規則；例如「沒講負責人就標待確認」這類規則，搬完還在。

## 作者做過的實驗／例子

- 原書把兩個 Gem（會議紀錄整理員、家長聯絡小幫手）轉成兩個資料夾，各一份 SKILL.md，打包 ZIP 匯回 Spark。Claude Code 版不必打包，資料夾放進 `.claude/skills/` 就生效。
- 匯入後用它整理虛構會議紀錄，仍保持三段結構，沒講負責人的標「待確認」。
- 搬之前提示詞鎖在平台裡；搬之後是純文字檔，Claude Code、Spark 等支援技能的工具都讀得懂。

## 演練

### 練習 1：把一段提示詞轉成 Claude Code 技能

**目的**：練習把散落的提示詞整理成「name＋description＋規則」的通用格式。
**送給練習視窗的提示詞**：

```text
下面是我（虛構）在別的 AI 平台調好的一段提示詞，請把它轉成一份 Claude Code 技能，存成 .claude/skills/meeting-notes-organizer/SKILL.md（相對於 practice/）。
虛構的原提示詞：「你是會議紀錄整理員。使用者會貼上一段雜亂的會議記錄。請整理成三段：一、會議決議；二、待辦事項（每項要有負責人與期限）；三、需要後續討論。如果記錄裡沒有提到負責人或期限，標示『待確認』，不要自己編。語氣簡潔，不要加評論。」
格式參考 Spark-skills/ 底下任一個 SKILL.md 的 frontmatter，但內容用上面這段重寫。
要求：name 用小寫連字號；description 寫清楚什麼時候該啟用，包含至少 4 種口語說法；正文規則逐條列出，「待確認」這條必須保留。
另存 ch08/ex1-notes.md，說明「搬家前後有哪些規則完整保留、有哪些你補充了」，以及這個資料夾放進 git 有什麼好處。
```

**觀察重點**：

- 原提示詞的每一條規則是否都在 SKILL.md 裡找得到？
- frontmatter 的 name 與 description 格式是否正確？
- 這個檔案是純文字：可以自己存、自己改、用 git 追蹤版本。

### 練習 2：用搬過來的技能處理資料，檢查規則有沒有跟著走

**目的**：驗證「搬走的不只是名字，是整套規則」。
**送給練習視窗的提示詞**：

```text
請使用 meeting-notes-organizer 技能（.claude/skills/meeting-notes-organizer/SKILL.md），處理下面這段虛構會議記錄，結果存成 ch08/ex2.md：
「週五小組會議。大家同意下週一開始試跑新流程。小美說她可以負責整理使用手冊，這個月底前交。阿宏說要找廠商報價，但沒講什麼時候。還有一個問題，是不是要多買兩台平板，大家意見不一，沒有結論。」
輸出三段結構。接著做規則檢查：逐條列出 SKILL.md 的每條規則，說明這次輸出有沒有遵守，特別是「沒負責人或期限就標待確認」那條。
最後說明：如果我把這個資料夾複製到另一台電腦的 Claude Code，或匯入其他支援技能的 AI，要怎麼直接使用、需不需要改什麼。
```

**觀察重點**：

- 阿宏的待辦有沒有被標「待確認」，而不是被自動補上期限？
- 「需要後續討論」那一段有沒有把沒結論的事放進去？
- 回答「換工具怎麼用」時，是否強調這份是純文字、不綁平台？

## 教練解說要點

- 重點是「提示詞資產化」：從鎖在平台裡變成自己手上、可版本控制的檔案。
- 檢查搬家成功的關鍵不是檔名，而是規則有沒有一條不漏地跟著走。
- 技能庫是 MIT 授權範例，可參考結構，自己的提示詞要自己改寫。
