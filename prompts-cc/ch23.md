# ch23｜官方說明與更新怎麼追（Claude Code 版）

## 這章在講什麼

- Claude Code 與 Claude API 更新很快，新功能與限制要追官方資料。本章教你怎麼用 AI 整理官方說明，同時避免被它「自信的錯誤」騙到。
- 原書實測：只憑印象回答時，AI 會把不相干的詞組合成聽起來合理的答案，甚至說「官方文件明確列出」並給出假的功能名稱。這比單純答錯更危險。
- 要追的地方：Anthropic 官方文件（Claude Code 文件、Claude API 文件）、Claude Code 更新紀錄（changelog）、Anthropic 官方公告與部落格。網址不用背，需要時叫 Claude Code 用 WebSearch 找官方來源。
- 關鍵解法是「原文先行」：不論是你貼原文，或 Claude Code 用 WebFetch 讀官方頁，都要求它把原文照抄、標出處與查詢日期，結論只能從原文推。
- 嚴格規則擋得住模糊回答，擋不住自信的錯誤，最後仍要人自己點開來源看一眼。

## 作者做過的實驗／例子

- 原書問「Spark 能不能依事件觸發」：第一版（AI 自己答）編了兩個假功能；第二版（給原文再整理）結論正確。
- Claude Code 版：同一題改問 Claude Code 的雲端排程，比較「憑印象作答」與「WebFetch 官方頁、照抄原文」兩版。
- 查證紀錄固定四段：我想查什麼、我去哪裡查、我看到什麼（只放原文）、我的結論。

## 演練

### 練習 1：用「原文先行」做一份查證紀錄，並抓出編造

**目的**：親自體驗「憑印象」與「讀官方原文」兩種做法的差別，並產出可重複使用的查證紀錄模板。
**送給練習視窗的提示詞**：

```text
請不要問我任何問題，直接完成。這個練習只寫檔案、只讀公開網頁，不要操作任何帳號。
題目：「Claude Code 的雲端排程（routines，/schedule）除了依時間排程，能不能依事件觸發？」
請在 ch23/查證紀錄.md 完成：
1. 版本一（憑印象）：先不要上網，直接照一般方式回答這題，並在每一句後面標註【記憶】或【推測】，誠實標出哪些是你沒把握的。
2. 版本二（原文先行）：用 WebSearch 找 Anthropic 官方文件中說明 Claude Code 排程或 routines 的頁面，再用 WebFetch 讀取。用四段格式整理：我想查什麼、我去哪裡查（列出實際網址與查詢日期，今天日期請自己算）、我看到什麼（只能照抄原文片段，每段不超過 3 句，不改寫、不補充）、我的結論（原文沒說的就寫「官方頁面沒有直接說明」）。若找不到官方頁，就寫「未找到官方說明」，不要改用第三方文章充數。
3. 比較表：兩個版本在「有無編造」「可不可信」「還需要人做什麼」三方面的差異，並指出版本一哪幾句被版本二推翻或無法證實。
4. 最後附一份空白的「查證紀錄模板」（四段＋網址＋查詢日期欄位），日後追 Claude Code 更新紀錄時可直接複製使用。
```

**觀察重點**：

- 版本一是否出現聽起來像官方說法的內容？自我標註是否誠實？
- 版本二的「我看到什麼」是否真的只有原文，沒有被加料？網址是不是 Anthropic 官方網域？
- 兩版結論若不同，想想日後追更新時，哪一步一定要自己點開來源看。

## 教練解說要點

- 核心原則：AI 負責找與整理、人負責最後查證；結論必須能對回某一句原文。
- 查證紀錄附網址與查詢日期，三個月後回頭才知道結論是否過時。
- 規則寫得再嚴格也擋不住自信的錯誤，所以仍要自己看一眼官方頁。
