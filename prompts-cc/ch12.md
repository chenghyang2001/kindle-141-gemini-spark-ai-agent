# ch12｜客戶關係與行銷小幫手

## 這章在講什麼

- 小店老闆最容易漏掉的，是客人不在時還記不記得他：誰快生日、誰很久沒來、這週該貼什麼、這個月賺多少。
- 這些「沒有截止日、只會安靜累積」的事，交給 AI 在開店前先備好。
- 資料庫多了客戶的偏好與紀錄，這是小店最珍貴、也最容易流失的資產。
- 成品：客戶名單、生日提醒與祝賀訊息、一週社群貼文、營收摘要，最後把規則存成 Claude Code 技能 marketing-helper。
- 做完之後，一句話（例如登記一位新客人與偏好）就能讓系統自己補齊欄位。

## 作者做過的實驗／例子

- 日期欄位踩坑：AI 為了「完整」自己補年份，試算表又把它轉成日期格式，兩層都出錯。解法是直接給完整文字，而不是叫它自己判斷後改正。
- 原書 Spark 沒有 Canva，促銷圖改用 Google Slides 做單頁再下載 PNG。Claude Code 版的生日提醒改成真的建在 Google 日曆。
- 最後用「登記一位新客戶……」這種一句話指令驗收技能是否生效。

## 演練

### 練習 1：客戶關係表與生日提醒

**目的**：把客戶名單、偏好、生日整理成可追蹤的表，並產出「近期誰生日、誰太久沒來」的提醒與祝賀訊息。
**送給練習視窗的提示詞**：

```text
請幫一家虛構的小咖啡店「晨光咖啡」建立客戶關係系統，資料全部虛構。本練習允許使用 Google 日曆連接器建立事件，標題一律以「課程練習」開頭，不得修改或刪除任何既有事件。
1. ch12/customer-crm.md：用表格做 8 位虛構客戶：編號、姓名（化名）、生日（只寫月-日，不寫年份，並註明此欄要存成純文字）、手機末三碼、來源、偏好、上次來店日、備註。請以今天日期為準，刻意讓 2 位在 7 天內生日、2 位超過 60 天沒來。
2. ch12/birthday-reminder.md：列出 7 天內生日的客人，各寫一則 50 字內的祝賀訊息（要用到該客人的偏好）；再列出超過 60 天沒來的客人與一句喚回話術。
3. 為 7 天內生日的客人各在 Google 日曆建一個全天事件，標題「課程練習-晨光咖啡-<化名>生日」，說明欄放祝賀訊息。
4. 最後附「我作為店長要自己核對什麼」：至少 3 點，包含日期欄位會不會被轉成日期格式。
不能寄信。把建立的日曆事件（類型、標題、ID）附加寫進 ch12/cleanup.md。
```

**觀察重點**：

- 生日欄有沒有避開年份、並提醒純文字格式（對照書中日期被兩層轉換的坑）？
- 日曆上是否真的出現「課程練習」生日事件，日期與 CRM 表一致？
- 「沒來很久」的判斷是否與 CRM 表的日期一致？可自己數一次。

### 練習 2：一週社群貼文與營收摘要，再封裝成技能

**目的**：把重複工作變成可複用的規則，理解為什麼要把規則寫進技能檔。
**送給練習視窗的提示詞**：

```text
延續晨光咖啡的情境，完成三件事：
1. ch12/social-posts.md：本週週一到週五各一則社群貼文，每則含主題、文案（80 字內）、建議貼文時間、需要什麼圖。
2. ch12/revenue-summary.md：自擬 10 筆虛構交易（日期、品項、金額），算出本月總營收、最暢銷品項、平均客單價，算式寫出來方便我驗算。
3. .claude/skills/marketing-helper/SKILL.md（相對於 practice/）：把上面兩件事和客戶登記的規則寫成 Claude Code 技能。frontmatter 有 name（小寫英文加連字號）與 description；description 要寫「當我說……時使用」這種觸發時機，不能只寫「做什麼」。正文要有工作流程、輸出格式、權限邊界（不得自動對外發送、不得改動既有資料）。
最後照技能執行一句話：「登記一位新客戶 小安，生日 3-08，喜歡燕麥拿鐵，朋友介紹」，把新增的一列附加到 ch12/customer-crm.md，並說明哪些欄位是你依規則補的、哪些留白。
```

**觀察重點**：

- description 寫的是「觸發時機」還是只在描述功能？
- 營收數字用計算機核對一次，算對了嗎？
- 一句話登記時，沒給的欄位（手機末三碼、上次來店日）是留白還是被編出來？

## 教練解說要點

- 「把答案直接給它」比「叫它自己判斷後改正」可靠得多。
- 不管 AI 說改好沒有，都要親自打開檔案或日曆看一眼。
- 技能的 description 決定什麼時候被叫出來，是最容易寫壞的一欄。
