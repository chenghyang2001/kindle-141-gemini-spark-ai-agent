# ch14｜Claude Code + GAS 雲端神搭配

## 這章在講什麼

- 到上一章為止都是「你交辦、AI 執行」。本章換一種合作方式：請 Claude Code 寫一支 Google Apps Script（GAS），貼進試算表後讓程式自己每天跑。
- 差別在於：AI 每次執行都耗額度、結果不完全一樣；程式則是同樣輸入永遠同樣輸出，而且幾乎沒成本。規則明確、每天重複的計算交給程式，需要理解與判斷的交給 Claude Code。
- 你不必會寫程式，但寫完要做「三邊數字對照」：程式算的、Claude Code 透過雲端硬碟連接器另外讀同一份表算的、你自己數的，三邊一致才可信。
- 四件成品：雲端硬碟上的值週紀錄試算表、可運作的 sendDailyDigest 程式、每日摘要（Claude Code 版改成只建 Gmail 草稿）、每日檢查排程（claude.ai routines）。

## 作者做過的實驗／例子

- 原書由 Spark 寫 GAS；本版改由 Claude Code 寫成 .gs 檔，再由你貼進 Apps Script。貼之前編輯器要全刪再貼，存檔後函式下拉選單才會出現函式名稱，第一次執行一定跳授權畫面。
- 原書驗收範例：總列數 12、已完成 9、未完成 3，三邊一致。Claude Code 版的第二邊改成「用 Google 雲端硬碟連接器直接讀試算表」，和程式邏輯完全獨立。
- 對不上時，先懷疑資料被改過，再懷疑程式；最常見原因是中間改了試算表卻沒重新執行。

## 演練

### 練習 1：請 Claude Code 寫 GAS 每日摘要程式

**目的**：體驗「說清楚需求，AI 產出程式碼」，並在真實雲端硬碟建好要讓程式讀的試算表。
**送給練習視窗的提示詞**：

```text
請為「值週紀錄表」寫 Google Apps Script，並在我的 Google 雲端硬碟建立測試用試算表。安全規則：雲端檔案標題一律以「課程練習」開頭、放在雲端硬碟資料夾「K141-課程練習」（不存在就建立）；不刪除、不修改任何非本次建立的檔案；程式不得寄信。
1. 在 ch14/daily-log.csv 自擬 12 列虛構資料，欄位：日期（月-日文字）、時段、項目、負責人、狀態（已完成/未完成）。其中 9 列已完成、3 列未完成。
2. 用 Google 雲端硬碟連接器（mcp__claude_ai_Google_Drive__create_file）把這份 CSV 建成 Google 試算表，標題「課程練習-值週紀錄表」，放進「K141-課程練習」。若無法轉成試算表格式，就上傳 CSV 並在回報中註明。
3. 在 ch14/sendDailyDigest.gs 寫 sendDailyDigest() 函式：讀取目前試算表的資料列（跳過標題列）、統計總列數／已完成／未完成、列出未完成清單、依負責人分組統計，組成內文後用 GmailApp.createDraft 建立草稿給目前使用者（主旨以「課程練習」開頭），絕不使用 MailApp.sendEmail 或 GmailApp.sendEmail。重要步驟用繁體中文註解寫「為什麼」；空表、缺欄位時用 Logger 記錄而不是中斷。
4. 檔案頂端用註解寫出：開啟試算表 → 擴充功能 → Apps Script → 全刪再貼 → 存檔 → 選函式執行 → 第一次會遇到的授權提示。這支程式你只寫檔，不執行。
5. 把本次建立的雲端物件（類型、標題、檔案 ID、所在資料夾）附加寫進 ch14/cleanup.md。
```

**觀察重點**：

- 程式有沒有只讀不改、不動原始資料，而且用的是「建草稿」不是「寄信」？
- 空表或缺欄位時是否有防護？
- cleanup.md 有沒有確實記下檔案 ID，方便事後清除？

### 練習 2：三邊數字對照與每日檢查排程

**目的**：重現「寫完後再驗一次」的習慣，用獨立方法對數字，並把每日檢查寫成排程設定。
**控制台接手**：控制台依 ch14/routine.md 用 `/schedule` 建立一個「課程練習-值週表每日檢查」雲端 routine，手動觸發跑一次確認能讀到試算表、只建草稿，再刪除該 routine，並把 routine 名稱與 ID 附加寫進 ch14/cleanup.md。
**送給練習視窗的提示詞**：

```text
延續練習 1。安全規則：只讀「課程練習-值週紀錄表」這一份檔案，不修改它；信件只能建草稿，絕不寄出；不碰其他雲端檔案。結果寫到 ch14/three-way-check.md：
1. 「程式算的」：不執行程式，照 sendDailyDigest.gs 的邏輯逐步推演它會輸出的總列數、已完成、未完成。
2. 「Claude Code 讀表算的」：用 Google 雲端硬碟連接器實際讀取「課程練習-值週紀錄表」重新計算一次，寫出你怎麼數；若讀不到雲端檔，改讀 ch14/daily-log.csv 並註明。
3. 把兩者放進同一個表格，第三欄「我自己數的」留空給我填。
4. 故意製造錯誤（只在推演中，不要真的改雲端檔）：假設有人把一列狀態改成「完成」（少一個「已」字），推演程式會怎麼數、三邊會出現什麼差異，以及我該先懷疑資料還是程式。
5. 在 ch14/routine.md 寫一份每日檢查排程設定：排程名稱「課程練習-值週表每日檢查」、每天早上 7 點（台北時間）、要給 routine 的完整提示詞（讀表 → 統計 → 數字異常時建立主旨以「課程練習」開頭的 Gmail 草稿，不寄出）、需要的連接器。你不要自己建立排程，由控制台接手。
```

**觀察重點**：

- 程式推演和連接器讀表的數字是否一致？不一致時有沒有誠實指出？
- 「已完成」被寫成「完成」這類拼字差異，是否被辨識為資料問題，並提出標準化狀態值的修補？
- routine 的提示詞有沒有把「只建草稿、不寄出」寫進去？

## 教練解說要點

- AI 寫的程式和人寫的一樣會錯，差別是你有沒有去驗。
- 驗證要用「獨立方法」：程式推演和連接器直接讀表是兩條不同的路，對得起來才可信。
- 對不上時的順序：先查資料被動過，再查程式；排程跑的東西更要先想好出錯時怎麼被發現。
