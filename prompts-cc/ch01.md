# ch01｜把需求講清楚，Claude Code 才做得對

## 這章在講什麼

- 作者提出「七個欄位」的指令骨架：目標、資料來源、執行步驟、判斷規則、輸出位置與格式、時間或觸發、權限邊界。這套骨架對 Claude Code 一樣適用。
- 前五欄說「要做什麼」；後兩欄（判斷規則、權限邊界）說「不要做什麼」，最容易被略過，卻最決定結果穩不穩。
- AI 會替你填空白。Claude Code 手上有寫檔、終端機、Gmail 連接器，你沒說不能寄信，它就可能覺得幫你寄出去很貼心；負面規則是在替它畫界線。
- 「壞問法」與「好問法」逐欄對照：七欄講完，結果就能被預測、被驗收。

## 作者做過的實驗／例子

- 原書：以虛構報名清單請 Spark 統計人數、依單位分組、列出特殊需求者，輸出成三段文件。Claude Code 版：同樣的任務，直接寫成本機 Markdown 檔，驗收一樣看三段、數字、有沒有多出資料。
- 驗收標準：若出現你沒給的欄位或人名，代表判斷規則寫得不夠硬。
- 同章附「七欄位範本」，把中括號換成自己的內容即可，之後每章都會沿用。

## 演練

### 練習 1：用七欄位寫一個完整指令並執行

**目的**：親手把一個模糊需求拆成七個欄位，並看到成果可驗證。
**送給練習視窗的提示詞**：

```text
請先自行虛構一份「社區讀書會報名清單」共 8 人（欄位：編號、姓名、所屬社群、角色、飲食備註；備註有的是「無」，有的是素食或過敏），存成 ch01/roster.md，並註明是虛構資料。
然後依下面七個欄位執行：
目標：整理成一份報名摘要。
資料來源：只用 ch01/roster.md，不要引用其他資料，不要上網。
執行步驟：(1) 統計總人數 (2) 依所屬社群分組算人數 (3) 把備註不是「無」的人單獨列表。
判斷規則：不要新增清單沒有的欄位，不要編造電話或電子郵件。
輸出位置與格式：ch01/ex1-summary.md，要有三個段落標題。
時間或觸發：現在執行一次。
權限邊界：不要呼叫任何 Gmail／日曆／雲端硬碟工具，不要修改 ch01/ 以外的檔案。
最後在檔案底部加一段「執行回報」，逐條說明你遵守了哪些限制。
```

**觀察重點**：

- 三個段落是否齊全？人數加總是否等於 8？
- 有沒有偷偷多出聯絡方式？沒有的話，是哪一條判斷規則擋住的？
- 「執行回報」是否具體，還是只寫「已完成」？

### 練習 2：好問法 vs 壞問法並排比較

**目的**：看到「只講一句」與「七欄講完」的產出差異，體會填空白的風險。
**送給練習視窗的提示詞**：

```text
針對同一個情境做兩次實驗：「幫我整理一份小型園遊會的攤位名單」。
先自行虛構 6 個攤位資料（註明虛構）。
實驗 A（壞問法）：當作我只說了「幫我整理這份名單」，你照自己的判斷整理，並誠實列出「自作主張清單」：哪些欄位、分類、內容是你自己補上去的。
實驗 B（好問法）：自己把七欄位寫完整（目標、資料來源只能用那 6 筆、步驟、判斷規則、輸出格式、觸發、權限邊界），把這份七欄位指令寫出來，再照著整理一次。
兩次實驗都只寫本機檔案，不要呼叫任何連接器工具。
把兩次結果與自作主張清單並排成表格，存成 ch01/ex2-compare.md，最後用三句話說明兩次的差異。
```

**觀察重點**：

- 實驗 A 的「自作主張清單」有幾項？是否出現你沒要的欄位或角色？
- 實驗 B 是否把這些空白都封住了？
- 哪一欄對縮小差異貢獻最大？通常是判斷規則與權限邊界。

## 教練解說要點

- 七欄位＝前五欄正面描述＋後兩欄負面界線；後兩欄要刻意練，因為人不習慣先想壞的那一面。
- AI 出錯常是「做太多」而不是「沒做」；Claude Code 能動的工具越多，權限邊界就越重要。
- 提醒觀眾：這章資料都是虛構，正式使用時「不要自己編造資料」這句一定要留著。
