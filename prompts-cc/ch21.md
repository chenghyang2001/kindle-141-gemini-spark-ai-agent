# ch21｜提示詞與指令資源（Claude Code 版）

## 這章在講什麼

- 網路上有很多別人寫好的 CLAUDE.md、Skills、提示詞可參考，但不能整段照抄：對方的檔名、流程、權限設定都跟你不同，抄來的東西也不會成為你的。
- 正確用法：看它的想法，用自己的欄位重寫。與第 19 章「拿骨架、內容自己寫」是同一個原則。
- 一段好指令有七個欄位：目標、資料來源、執行步驟、判斷規則、輸出位置與格式、時間或觸發、權限邊界。Claude Code 會真的動手讀寫檔案、操作連接器，權限邊界沒寫就等於讓它自己判斷。
- 同一件事有壞講法與好講法：好的講法都把「範圍」和「界線」講死。
- 使用注意：佔位符要留白由自己填；「寫指令的 Skill」不要讓它順便執行指令。

## 作者做過的實驗／例子

- 原書用 Spark 對照「幫我整理收件匣」與「限定過去 24 小時未讀信、分三類、每封一句摘要」；Claude Code 版同樣適用，而且可把好講法存成 Skill 重複觸發。
- 原書提醒「回覆這封信」可能被直接寄出；Claude Code 接上 Gmail 連接器後也一樣，好的講法是「用 create_draft 存草稿、不要寄出」。

## 演練

### 練習 1：把網路上的粗糙指令，改寫成七欄位範本庫

**目的**：把「看想法、自己重寫」做成自己的 Claude Code 提示詞範本庫，並且每則都有權限邊界。
**送給練習視窗的提示詞**：

```text
請不要問我任何問題，直接完成。這個練習只寫檔案，不要操作 Gmail、日曆、雲端硬碟或任何外部服務。
請自行虛構 4 句「從網路抄來的粗糙指令」，例如：「幫我整理一下收件匣」「把資料寫進試算表」「回覆這封信」「每天提醒我」。
請在 ch21/提示詞範本庫.md 完成：
1. 先列出七個欄位：目標、資料來源、執行步驟、判斷規則、輸出位置與格式、時間或觸發、權限邊界。
2. 對每句粗糙指令，先寫「壞在哪」（一行），再用七欄位改寫成可直接貼給 Claude Code 的完整指令；資料來源、檔名、資料夾名稱用【括號佔位符】留白，不要自己填實際內容。
3. 每則的權限邊界必須明確寫出「能做什麼、不能做什麼」，並寫出對應的 Claude Code 做法，例如：信件只用 create_draft 存草稿、絕不用 send_message 寄出；不刪除、不封存非本次建立的東西；排程只寫設定草稿、不直接建立 routine。
4. 從 4 則中挑 1 則，另外寫成一個 Skill 草稿，放在同一份檔案的最後一節（不要另建 .claude/skills 資料夾）：含 frontmatter 的 name 與 description，description 要寫清楚觸發與不觸發的情境，內文註明「這個 Skill 只產生指令，不執行」。
5. 最後附一段「使用前檢查表」：5 條勾選項，用來確認自己真的改過一遍、不是照抄。
```

**觀察重點**：

- 每則是否都有權限邊界？寫的是具體界線（create_draft、不刪除），還是籠統的「請小心」？
- 佔位符有沒有被偷偷填成編造的內容？
- Skill 草稿的 description 是否把「不觸發」也寫清楚，避免誤觸發。

## 教練解說要點

- 資源只能當靈感來源，七欄位才是自己的骨架；範本庫與 Skill 的價值在「可重複套用」。
- Claude Code 真的會動手，權限邊界是擋住它自作主張的最後一道牆。
- 「寫指令」與「執行指令」要分開，這是安全使用代理人的基本習慣。
