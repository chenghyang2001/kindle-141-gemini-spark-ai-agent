# ch19｜Spark 技能庫

## 這章在講什麼

- 作者把自己教學與工作現場用過的 25 個技能整理成一個技能庫，授權是 MIT，可以直接拿去用、改，甚至商業使用，唯一要求是保留授權聲明。
- 本章教你三件事：看得懂一個技能庫（知道去哪找、怎麼判斷能不能用）、用技能庫的骨架做出自己的借閱表、照技能庫的骨架自己重寫一個中文版技能。
- 每個技能都是一個資料夾，裡面一份 SKILL.md；開頭一定有 name 與 description。description 要寫觸發時機（當我……時使用），不能只寫做什麼。
- 挑選原則只有一句：找最像的，不是找最厲害的。愈像，要改的地方愈少。
- 建議先看 otto-skill：它不是直接使用的技能，而是幫你生出骨架的技能。
- 授權要先看：個人、教育、內部使用都可，商業使用也行，但要保留聲明。

## 作者做過的實驗／例子

- 範例是班級圖書借閱表：B01 到 B05 先手動建好，B06 是技能寫進去的，只打一句「借出某書給某人」，編號、借出日、應還日、狀態由技能自己補齊，因為規則寫在技能裡。
- 作者選的是「試算表與自動化」這一類，理由是借閱表本質上就是一張要持續維護的試算表。
- 並說明為什麼不是每個技能庫都能這樣直接拿：要先看授權。

## 演練

> 說明：練習視窗工作目錄裡已有 Spark-skills/（技能庫）。請讓它真的去讀技能檔再做事，不要憑印象。技能檔路徑從 Spark-skills/README.md 與 Spark-skills/skills/ 找。

### 練習 1：讀懂技能庫並挑選最像的三個

**目的**：練習「看得懂一個技能庫」：先讀說明、再挑最像的，而不是最強的。
**送給練習視窗的提示詞**：

```text
我是一位虛構的小學班導「林老師」，常做的事：整理班級圖書借閱、把家長聯絡單整理成通知、把會議筆記寫成紀錄。
請先實際讀 Spark-skills/README.md，再打開 Spark-skills/skills/ 底下與我的需求最像的三個技能的 SKILL.md（例如 02_sheets-and-automation/google-sheets-gas-builder、04_docs-and-slides/humanizer-zh-tw、01_start-here/otto-skill 或 01_start-here/skill-installer，請你自己判斷，不要只挑我舉的例子）。
把結果存到 ch19/pick-skills.md，用表格呈現：技能名稱（資料夾路徑）、description 原文的重點（用自己的話）、觸發時機是什麼、跟我的需求相似度（高/中/低）與理由、我需要改哪裡、有沒有權限風險（會不會寄信、改檔案、連網）。最後說明為什麼你選「最像的」而不是「功能最多的」，並判斷哪一個 description 寫得最好、哪一個還能改進。
```

**觀察重點**：

- 它是否真的讀了檔案？表格中的內容能否在 SKILL.md 找到對應？
- 相似度判斷是否有理由，不是亂給？
- 權限風險欄有沒有指出實際會碰到的動作，而不是泛泛而談？

### 練習 2：套用技能庫的技能做出借閱表

**目的**：親眼看到「規則寫在技能裡，一句話就能補齊欄位」，並理解技能被實際套用的樣子。
**送給練習視窗的提示詞**：

```text
請實際讀 Spark-skills/skills/02_sheets-and-automation/google-sheets-gas-builder/SKILL.md，並依其中規則（工作流程、輸出格式、權限邊界）完成下面任務。你不能執行程式，GAS 只寫成 .gs 檔。
任務：為虛構的班級圖書借閱表做自動化。
1. ch19/book-tracker.csv：自擬 5 筆已有的借閱紀錄（編號 B01 起、書名、借閱人（化名）、借出日、應還日、狀態、備註），借期 14 天。日期用「月-日」文字。
2. ch19/lend.gs：寫一支 lendBook(bookTitle, borrower) 函式，對應我說一句話「借出 某書 給 某人」時，自動補齊下一個編號、借出日、應還日（+14 天）、狀態「借閱中」。要有繁體中文註解、錯誤處理（找不到工作表、書名空白），不得改動既有列，不得寄信。
3. ch19/skill-applied.md：列出你讀 SKILL.md 後套用了哪幾條規則（引用其標題或小節名稱，不要整段貼），沒套用的規則也說明原因。
4. 最後模擬一次：我說「借出 想飛的鋼琴少年 給 黃品瑄」，寫出會新增的 B06 那一列資料。
```

**觀察重點**：

- skill-applied.md 提到的小節是否真的存在於 SKILL.md？
- 程式有沒有越過權限邊界（改既有列、寄信）？
- B06 的編號、日期是否與前五筆自洽，14 天計算有沒有錯？

### 練習 3：照骨架重寫一個自己的技能，並確認授權

**目的**：不是整份照搬，而是理解骨架後用自己的語言重寫，並做授權檢查。
**送給練習視窗的提示詞**：

```text
請先讀 Spark-skills/skills/01_start-here/otto-skill/SKILL.md 與 Spark-skills/LICENSE（若存在；不存在就讀 README 裡的授權說明），再存到 ch19/：
1. license-check.md：用自己的話回答：這個技能庫是什麼授權、我可以做什麼、有什麼唯一要求、如果我做成付費課程要怎麼處理。
2. course-book-tracker/SKILL.md：照技能庫的骨架，自己重寫一個「班級借閱表」技能（繁體中文）。結構：name（小寫英文加連字號）、description（要寫「當我……時使用」）、主要目標、工作流程（我說什麼它做什麼，至少 3 個指令範例）、輸出格式、驗收規則（做完要請我自己開檔案確認）、權限邊界（至少 4 條不准做的事）。不得複製原文整段，要用自己的話。
3. rewrite-notes.md：列出你從骨架學到的三件事，以及你跟原技能不同的兩個地方與理由。
```

**觀察重點**：

- 授權說明是否正確（MIT：保留授權聲明、可商用）？
- description 是否寫成觸發時機？
- 重寫版是否不是原文的翻譯，而是真正改成借閱表的版本？

## 教練解說要點

- 找最像的，不是找最厲害的；愈像要改的愈少。
- 技能的核心是 name 與 description，description 決定什麼時候被叫出來。
- 技能庫可以直接用，但仍要「照骨架自己重寫一次」才算學會；授權要先看，MIT 要保留聲明。
- 套用技能時要確認它真的讀了檔案：可以抽查它引用的小節是否真的存在。
