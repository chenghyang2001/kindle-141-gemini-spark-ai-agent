# ch26｜NVIDIA Build 免費 AI API

## 這章在講什麼

- 上一章的通用金鑰要付費；本章改用有免費額度的 NVIDIA API，額度足夠個人測試學習。
- 有了免費額度，就能做平常捨不得做的事：同一個問題讓兩個不同模型同時回答，並排比較。
- 並排比較的價值：兩邊說一樣的部分大概可靠，差很多的部分要自己判斷。
- 作者用三題測試得到的觀察：一個比較簡潔、一個比較完整；翻譯兩邊都對但語感不同；一個答案比較有想法但也比較長。結論是沒有哪個模型永遠比較好，要看用途。
- 與上一章整合式服務比較：免費額度適合先試用，但清單上有的模型不一定叫得動；要長期穩定或指定模型，再考慮付費。

## 作者做過的實驗／例子

- 在試算表放三題，兩欄各由一個模型回覆。驗收項目：有開發者帳號與金鑰、三題兩欄都有回覆、金鑰放在指令碼屬性。

## 演練

### 練習 1：設計「雙模型並排比較」表與評分準則

**目的**：不實際呼叫，先練習怎麼設計一份能真正看出差異的比較實驗。
**送給練習視窗的提示詞**：

```text
你扮演 Spark 的助教。不能連網、不能用金鑰，請用佔位符，並且不要問我任何問題。
請在 ch26/雙模型比較設計.md 完成：
1. 為一位虛構的國中英文老師設計三道測試題（一題摘要、一題翻譯、一題開放式建議），說明為什麼這樣選。
2. 做一張並排比較表：欄位為題目、模型 A 回覆、模型 B 回覆、相同處、差異處、我的判斷、採用哪個。模型回覆欄請寫「待填」，不要自己編造兩個模型的答案。
3. 寫評分準則：準確、簡潔度、語感、是否有想法、長度是否適合用途，各 1 到 5 分並說明給分標準。
4. 寫一段 Apps Script 呼叫流程的偽碼（不是可執行程式）：金鑰從指令碼屬性讀取、同題呼叫兩個模型、遇到某個模型叫不動時要記錄錯誤而不是中斷。
5. 加一小段「免費額度與付費服務怎麼選」的決策建議，不要編造數字。
```

**觀察重點**：

- 「模型回覆欄」是否守住「待填」，沒有編造兩邊答案？
- 評分準則是否可操作，另一個人照著打分數能得到接近的結果嗎？
- 偽碼有沒有處理某個模型失敗的情況。

## 教練解說要點

- 並排比較的目的是找出「共識」與「分歧」，分歧處才需要人判斷。
- 選型應從用途出發；先用免費額度跑通流程，再評估是否值得付費。
- 設計好比較表，日後換模型時可重複使用。
