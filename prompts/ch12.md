# ch12｜客戶關係與行銷小幫手

## 這章在講什麼

- 小店老闆最容易漏掉的不是服務當下，而是客人不在時還記不記得他：誰快生日、誰很久沒來、這週該貼什麼、這個月賺多少。
- 作者把這些「沒有截止日、只會安靜累積」的事，交給 Spark 在開店前先備好，放在同一份文件裡。
- 本章資料庫多了一樣東西：客戶的偏好與紀錄，這是小店最珍貴、也最容易流失的資產。
- 六件成品：客戶名單、生日提醒與祝賀訊息、一週五則社群貼文、促銷圖卡、營收摘要，最後把規則存成一個技能 marketing-helper。
- 做完之後，只要一句話（例如登記一位新客人與其偏好）就能讓系統自己補齊欄位。

## 作者做過的實驗／例子

- 日期欄位踩坑：AI 為了「完整」自己補上年份，試算表又把它轉成日期格式，兩層都出錯。解法是直接把完整文字給它，而不是叫它自己判斷後改正。
- Spark 的連結應用實機只有四個開關，沒有 Canva，所以促銷圖改成用 Google Slides 做單頁、自己微調後下載 PNG，好處是可編輯。
- 最後用「登記一位新客戶……」這種一句話指令驗收技能是否生效。

## 演練

> 說明：練習視窗的 Claude 扮演 Spark，不能真的連 Google 試算表，所以一律把「Spark 會產出的東西」存成檔案。

### 練習 1：客戶關係表與生日提醒

**目的**：體驗把客戶名單、偏好、生日整理成一張可追蹤的表，並產出「今天誰生日、誰太久沒來」的提醒與祝賀訊息。
**送給練習視窗的提示詞**：

```text
請你扮演 Gemini Spark，幫一家虛構的小咖啡店「晨光咖啡」建立客戶關係系統。資料請你自己編：
1. 在 ch12/customer-crm.md 用表格做 8 位虛構客戶：編號、姓名（用化名）、生日（只寫月-日，不要年份，並註明此欄要存成純文字）、手機末三碼、來源、偏好、上次來店日、備註。
2. 另外在 ch12/birthday-reminder.md 假設「今天是 11-14」：列出 7 天內生日的客人，各寫一則 50 字內的祝賀訊息（要用到該客人的偏好），再列出超過 60 天沒來的客人與一句喚回話術。
3. 最後附一段「我作為店長要自己核對什麼」：至少 3 點，包含日期欄位會不會被轉成日期格式。
不能寄信、不要真的存取任何服務，全部以檔案呈現。
```

**觀察重點**：

- 生日欄有沒有避開年份、並提醒純文字格式（對照書中日期被兩層轉換的坑）？
- 祝賀訊息是否真的用到偏好，還是千篇一律？
- 「沒來很久」的判斷日期是否與 customer-crm 表內的資料一致？可自己數一次。

### 練習 2：一週社群貼文與營收摘要，再封裝成技能

**目的**：看 Spark 如何把重複工作變成可複用的規則，並理解為什麼要把規則寫進技能檔。
**送給練習視窗的提示詞**：

```text
延續晨光咖啡的情境，請扮演 Spark 完成三件事，全部存到 ch12/：
1. social-posts.md：一週（週一到週五）各一則社群貼文，每則含主題、文案（80 字內）、建議貼文時間、需要什麼圖。
2. revenue-summary.md：自擬 10 筆虛構交易（日期、品項、金額），算出本月總營收、最暢銷品項、平均客單價。請把算式寫出來，方便我自己驗算。
3. marketing-helper/SKILL.md：把上面兩件事的規則寫成一份技能檔。開頭要有 name（小寫英文加連字號）與 description；description 要寫「當我說……時使用」這種觸發時機，不能只寫「做什麼」。正文要有工作流程、輸出格式、權限邊界（例如：不得自動對外發送、不得改動既有資料）。
```

**觀察重點**：

- description 寫的是「觸發時機」還是只在描述功能？
- 營收數字用自己的計算機核對一次，算對了嗎？
- 權限邊界有沒有明確寫出「不准做什麼」？

## 教練解說要點

- 重點不是 Spark 本身，而是「把答案直接給它」比「叫它自己判斷後改正」可靠得多。
- 無論 AI 說改好與否，都要親自打開檔案看一眼。
- 技能的 description 決定什麼時候被叫出來用，是最容易寫壞的一欄。
