# ch25｜AI 模型 API 資源

## 這章在講什麼

- 本章教你讓試算表或 Apps Script 去呼叫其他 AI 模型的 API，把 Spark 之外的模型也接進工作流。
- 使用 API 需要金鑰，且通用金鑰通常要付費。作者示範的是透過整合式服務（如 OpenRouter）用一把金鑰呼叫多個模型。
- 一個踩坑：有些模型會先在內部「思考」，思考本身也消耗額度，所以回應長度上限等於推理用量加回答用量。上限設太小時，回傳的結束原因是 length 而不是 stop，內容還是空的，調大上限即可。
- 中文比英文耗用 token，給中文任務時上限要開更大。
- 金鑰的正確放法：放在專案設定的指令碼屬性，絕對不要寫進程式碼。

## 作者做過的實驗／例子

- 實測某模型光推理就用掉 800 多個 token，額度設 800 時完全輪不到答案。
- 示範把金鑰存進指令碼屬性，程式只讀取名稱，畫面上的值是遮蔽的。

## 演練

### 練習 1：依情境挑模型，寫呼叫草稿與金鑰安全檢查表

**目的**：不碰任何真金鑰，練習「選型、寫草稿、排錯、守住金鑰」四件事。
**送給練習視窗的提示詞**：

```text
你扮演 Spark 的助教。不能連網、不能填任何金鑰，請全程使用佔位符【YOUR_KEY】，不要問我任何問題。
請在 ch25/api-規劃.md 完成：
1. 虛構三個老師情境（例如：批改短文給回饋、把家長通知翻成英文、把一週課表整理成表格），為每個情境寫選模型的考量（成本、速度、是否需要推理、中文品質），不要編造具體價格或確切模型名稱，不確定的寫「需自行查證」。
2. 用 Apps Script 風格寫一份「呼叫某 AI 模型 API」的程式碼草稿（請勿執行）：金鑰從指令碼屬性讀取、設定 max_tokens、檢查回傳的結束原因、錯誤時輸出可讀訊息。程式裡不可出現任何金鑰字串。
3. 一份「排錯速查」：當回傳內容是空的而結束原因是 length 時，原因是什麼、怎麼處理、為什麼中文要把上限開更大。
4. 一份「金鑰安全檢查表」6 條勾選項。
結尾註明：這份草稿從未實際執行，欄位與端點須人工驗證。
```

**觀察重點**：

- 程式碼草稿裡有沒有硬寫金鑰？檢查表是否涵蓋「不貼進對話、不放進共用文件」。
- 排錯那節是否準確解釋「推理也吃額度」？
- 選模型有沒有編造價格或型號？「需自行查證」是否出現。

## 教練解說要點

- 金鑰等於密碼：放指令碼屬性、不寫進程式、不外流，是本章最重要的規矩。
- 內容為空不一定是壞掉，先看結束原因再調上限。
- 選模型要看用途，不存在永遠最好的模型。
