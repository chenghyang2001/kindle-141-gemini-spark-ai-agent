# ch20｜免費資料與 API 大補帖

## 這章在講什麼

- 試算表裡的資料多半是自己輸入的，但天氣、書目等公開資料其實免費可取。本章教你讓 Spark 把這些外部資料接進自己的表。
- 作者特別區分：看網頁（轉述網頁內容）和呼叫 API（拿到結構化的數字）是兩回事。
- 怎麼挑 API：先看公開 API 清單中每一列的「是否需要金鑰」欄位，初學者優先選不用申請金鑰的。
- 請 AI 寫程式時要交代四件事：資料在哪、回傳長什麼樣、缺資料怎麼辦、格式限制（例如不放金鑰、不加沒要求的功能）。
- 書中列了幾個不用金鑰就能練習的免費 API（天氣、書籍、遊戲角色、圖片類）。

## 作者做過的實驗／例子

- 示範一：抓天氣預報寫進試算表。示範二：用書名查書籍資料，缺的欄位填「未提供」而不是留下 undefined。
- 重點：把回傳的 JSON 結構明確貼給 AI，不讓它猜欄位名稱。

## 演練

### 練習 1：依情境選 API，寫呼叫草稿（不執行）

**目的**：練習「看 Auth 欄位挑 API」與「四件事交代」，把它做成一份可以重複用的選型筆記。
**送給練習視窗的提示詞**：

```text
你現在扮演 Spark 的助教。請你自己虛構三個情境（例如：「週末要不要帶傘」「想知道某本書有沒有出版社資料」「班上要做隨機抽籤頭像」），不要問我任何問題。
請在 ch20/api-選型筆記.md 裡完成：
1. 一張表，列出 5 個你知道的「不需要申請金鑰」的免費公開 API 類型（只寫名稱與用途，不要編造網址，不確定的標註「需自行查證」），並標出每個適合上面哪個情境。
2. 對三個情境各寫一段「給 AI 的寫程式指令草稿」，必須包含四件事：資料在哪、回傳長什麼樣（請自擬一小段 JSON 範例）、缺資料怎麼辦（填「未提供」，不可出現 undefined）、格式限制（不放金鑰、不加沒要求的功能）。
3. 最後加一節「這份草稿我沒有實際呼叫過」，誠實列出哪些細節（欄位名、網址）是需要人工驗證的。
這是一份草稿，請不要真的連網或執行任何程式。
```

**觀察重點**：

- 四件事是否每個情境都齊全？「缺資料怎麼辦」有沒有寫成具體字樣？
- AI 有沒有編造看似真實的網址或欄位？「需自行查證」的標註是否誠實？
- 對照書中「API 回來的是結構化數字，不是網頁轉述」，看草稿是否清楚分開這兩件事。

## 教練解說要點

- 本章精神：外部資料要「可重複取得」，所以用 API 取代人工複製；而挑 API 的第一個濾網是金鑰需求。
- 指令寫法的關鍵是把結構給足，AI 就不必猜；猜就容易出錯。
- 提醒觀眾：這個練習只產出草稿，實際上線前必須自己小量測試一次。
