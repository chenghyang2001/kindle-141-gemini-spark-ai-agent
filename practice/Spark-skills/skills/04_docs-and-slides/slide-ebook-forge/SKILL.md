# slide-ebook-forge · 簡報電子書產線

把**已經做出來、可以跑的實作專案**，變成一本有**真實機截圖**的教學單元書
（簡報式 HTML ＋ 成書 PDF 雙輸出）。

> **本 skill 的來源**：`F:\GAS\` 專案已驗證成功的產線
> （用這套工法出了 U01～U09 共 9 本書並全部上線）。
> 這裡把該專案的工法抽象成可重複使用的 skill。

## 這支 skill 的定位（**先確認用對了**）

### ✅ 本 skill 完整包含這四件事（缺一不可，這就是它存在的理由）

| 含 | 在哪一節 | 內容 |
|---|---|---|
| ✅ **實作驗證** | §2 | 程式要先跑過測過，**寫出數字**（例：114/114 項全過） |
| ✅ **實機截圖產線** | §3 | 真 Chrome ＋ CDP 9222 ＋ playwright，截真圖 |
| ✅ **截圖標註** | §4 | PIL 紅框／數字圓標／說明籤／遮蓋日期帳號金鑰 |
| ✅ **簡報＋電子書雙輸出** | §5 | 同一份 template 出翻頁簡報 HTML ＋ 成書 PDF |
| ✅ **課程網站承載** | §7 | 卡片牆首頁 → 點進去 → 閱讀器（翻頁／目錄／縮放／整頁／雙頁／放大鏡／畫線註記／程式碼下載） |

> **這五段合起來才是完整產線。** 少了實作驗證＝交付沒跑過的程式；
> 少了實機截圖＝只能用假圖（違反鐵律）；
> **少了網站＝一堆 HTML 檔散在資料夾，學員不知道從哪開始。**
> 交付物不是「幾個檔案」，是**一個打開就能用的東西**。

### 什麼時候改用別支

| 你的狀況 | 用哪一支 | 為什麼不用本支 |
|---|---|---|
| 只有**主題**，還沒有實作 | `book-forge` | 沒有實作就截不到真圖，本支的產線跑不動 |
| 只要**簡報視覺樣板** | `teaching-slide-dna` / `presentation-templates` | 那些不含實作驗證與截圖產線 |
| 把一堆 md 做成**側邊欄網站** | `sidebar-web` | 不同交付形式 |

**本 skill 的不可取代性＝「實作驗證 ＋ 實機截圖標註」那兩段**——
現有其他 skill 都沒有做這件事。有可跑的專案要出教材，就用這支。

## 零、六段產線

```text
① 實作驗證   → 程式要先跑過、測過（不是「應該會動」）
      ↓
② 實機截圖   → 真 Chrome + CDP 9222 + playwright，截真圖（絕不偽造）
      ↓
③ 標註加工   → PIL 畫紅框、數字圓標、說明籤；遮蓋日期/帳號/金鑰
      ↓
④ 排版成書   → 程式碼分段上色注入 template → 簡報 HTML ＋ PDF
      ↓
⑤ 歸檔交付   → 程式碼進下載區、PDF 進交付夾、更新進度檔
      ↓
⑥ 網站承載   → 卡片牆首頁 ＋ 電子書閱讀器（翻頁／目錄／註記／程式碼）
```

> ⚠️ **第⑥段最容易被漏掉。** 書做完了就以為結束，但學員拿到的是
> 一堆散落的 HTML 檔，不知道要開哪個。**沒有網站，教材等於沒交付完。**

**核心價值**：每段都留**可查證的實體證據**——
不是「我覺得可以了」，而是「測試 114 項全過、截圖 32 張、實機驗證通過」。

## 一、🔴 三條鐵律（違反就重做，不接受解釋）

### 1. 截圖絕不偽造

> 教學截圖、示範結果**一律用真實操作產生**，絕不用假圖或憑空捏造的畫面魚目混珠。
> 無法實機取得的畫面，**必須明確標示「示意」**。

### 2. 金鑰與個資不進成品

日期時間、個人帳號 Email、API 金鑰、學生姓名——**一律遮蓋**（見 §3）。
真實憑證只放**部署資料夾外**的 `_帳密備忘_勿上傳.md`。

### 3. 改 template，不改產出檔

`<單元>_ebook.html` 是 build 腳本**自動產生**的，改了會被覆蓋。
**內容一律改 `<單元>_ebook_template.html`。**

## 二、① 實作驗證

**不准交付沒跑過的程式。** 依專案類型選驗證方式：

| 專案型態 | 驗證方式 | 通過標準（要寫出數字） |
|---|---|---|
| 後端／腳本 | 離線測試（Node.js / pytest 模擬環境） | 例：`114/114 項斷言全過` |
| 網頁 | Playwright ＋ Console 錯誤數 | 主要互動可操作、Console 無紅字 |
| 影像辨識 | 用真實測試資料跑，比對人工標準 | **寫出實測正確率**，不是「可以辨識」 |
| 工作流 | 用樣本資料跑完整流程 | 輸出結構正確 |

### ⚠️ 離線測試抓不到、只有實機才現形的坑

`references/known-traps.md` 收錄了 GAS 專案實際踩過的雷（**開工前先讀**），包含：
LLM 思考預算吃掉 maxOutputTokens、`String(undefined)` 是五個字、
平台偷改欄位名稱、replyToken 30 秒時效。

> **牽涉外部 API 的功能，一定要真的打一次。**

## 三、② 實機截圖：真 Chrome ＋ CDP

### 工法（已驗證數百張，穩定）

```text
啟動真的 Chrome，開遠端偵錯埠 9222
      ↓
playwright 連上這個 Chrome（不是開無頭瀏覽器）
      ↓
腳本一步步操作，每步截圖 → raw_<語意名>.png
```

**為什麼用真 Chrome 而非無頭**：
- 同一個 profile **免每次重新登入**（OAuth 授權流程很長）
- 截出來就是學員實際看到的畫面
- 已驗證：GAS 專案 U01～U09 全部這樣截

啟動指令與連接程式碼見 `scripts/launch_chrome_cdp.md`。

### 檔名規則

`raw_<語意步驟名>.png`（例：`raw_menu.png`、`raw_key_prompt.png`）
—— **用語意命名，不要 `raw_01.png`**，否則插圖時對不上。

自動化腳本放 `<工作區>/real/_自動化腳本/`。

## 四、③ 標註：`scripts/annotate_kit.py`

提供四個函式（直接 import 用）：

| 函式 | 作用 | 樣式 |
|---|---|---|
| `frame()` | **圈選框**：框出要看的地方 | 紅 `(229,57,53)`，圓角 10，半透明外暈 |
| `badge()` | **數字圓標**：標 1、2、3 順序 | 紅底白字圓形，半徑 17，白外圈 |
| `pill()` | **說明籤**：貼一句話解釋 | 藥丸型，teal/orange/navy |
| `cover()` | **遮蓋**：蓋掉不該出現的 | 見下表 |

字型：`C:\Windows\Fonts\msjhbd.ttc`（粗）、`msjh.ttc`（一般）。

### 🔴 必須遮蓋

| 要蓋掉 | 換成 | 為什麼 |
|---|---|---|
| 日期、時間戳 | 「（時間）」「（自動填入）」 | **教材不能有時效感** |
| 個人帳號 / Email | 遮蓋或假帳號 | 隱私 |
| API 金鑰、token | 一律遮蓋 | 金鑰絕不進散布檔案 |
| 人臉 | 依肖像同意決定 | 肖像權 |
| 學生姓名、學校 | 假資料 | 個資 |

### 產出

- 原圖 `real/raw_*.png`（**保留別刪**，之後要重標註）
- 成書圖 `real/annotated/m01.png、m02.png…`
- **尺寸對照表** `real/_圖片尺寸對照.md`

### 尺寸對照表（**先做表再寫書稿**，省下大量調圖時間）

版面：可用寬 174mm、一頁可用高 254.5mm。

| 圖 | 內容 | 像素 | width | 印出 (mm) |
|---|---|---|---|---|
| m01 | 成果圖：… ★ | 1387x119 | **96%** | 167.0 x 14.3 |

```html
<img class="shot" style="width:NN%;margin:0 auto" src="real/annotated/mNN.png" alt="">
```

★ ＝ 重點圖。產生對照表用 `scripts/make_size_table.py`。

## 五、④ 排版成書：`scripts/build_book.py`

```text
書稿  <單元>_ebook_template.html   ← 改這個
程式碼 原始程式檔（單一事實來源）
      ↓  build_book.py
      ↓  依行號切段 → 語法上色 → 注入 <!--G1--> 標記 → 頁碼重編
產出  <單元>_ebook.html            ← ⚠️ 自動產生，別手改
      ↓
簡報 HTML（翻頁）＋ 列印成 PDF
```

### 三個關鍵規則

1. **每段 ≤ 28 行**
   實測：一頁程式碼超過 28 行又要放 3 個解說框就**溢頁**，長函式一律拆兩段。
   **每一行都要涵蓋、不重疊**（`build_book.py` 會檢查）。
2. **語法上色的雷**
   字串佔位符若只用數字，會被「數字上色」規則吃掉，字串內容全變 0／1。
   已改用 `\x00STR<n>\x00` 當佔位符。
3. **頁碼自動重編**：封面不編號，之後每頁依序填 `02`、`03`……

### 雙輸出

| 輸出 | 用途 | 版型 |
|---|---|---|
| **簡報 HTML** | 課堂投影、線上瀏覽 | 翻頁式，一頁一重點 |
| **成書 PDF** | 學員下載珍藏 | 淺色書籍版型 |

兩者共用同一份 template，用 CSS `@media print` 切換。

| 要什麼 | 用哪份 |
|---|---|
| **新單元起手式**（空殼） | `assets/範本_單元電子書.html` |
| **看做完長什麼樣**（已上線的真實例） | ⭐ `assets/範例_已完成單元/` |

> 寫書稿前**先開 `範例_已完成單元/範例_書稿template_P1.html` 看一遍**——
> 那是一個真的做完、17 頁、11 張真圖、已上線的單元，
> 八區塊各該寫多長、圖怎麼插、程式碼怎麼切段，看它最快。

## 六、⑤ 書稿八區塊（**順序勿改**）

```text
封面 → ① ~ ⑧ → 版權頁
```

| # | 區塊 | 內容 |
|---|---|---|
| ① | **先看成果** | 完成畫面截圖，讓學員**先知道終點長什麼樣** |
| ② | **Vibe Coding：把需求講清楚** | 好問法／壞問法**對比** ＋ 完整提示詞（可整段複製）＋**為什麼這樣寫** |
| ③ | **這個單元在做什麼** | 學完你會＋流程圖＋關鍵觀念＋應用延伸 |
| ④ | **老師說** | 為什麼學這課、會多學到什麼、讓學員放心的事、**卡住了先看這三招** |
| ⑤ | **跟著老師做一次** | 分解步驟，每步搭**實機截圖**（圈選框＋數字圓標＋說明註解） |
| ⑥ | **程式碼全文與中文解說** | 程式碼**全文照登**，每段附白話解說（做什麼、哪裡可改） |
| ⑦ | **成果驗收清單** | 逐項打勾 |
| ⑧ | **程式碼下載說明** | 檔案名稱（部署後補網址） |

可加非編號補充頁，例如「**用在你自己的場合，要改哪裡**」對照表（實測對學員很有幫助）。

### 🔴 口吻與禁止事項

- **全書給學員看，一律書面口吻**（作者對讀者說話）。
  **嚴禁**「照著念」「口語稿」「邊示範邊念」等後台字眼出現在書裡。
- ❌ **不出現任何年份、日期**（避免時效感）
- ❌ 不出現「共 N 字」「共 N 頁」等統計數字
- ❌ 不放「下一單元預告」（單元順序可能調整）

### 視覺風格

- **質感要像市面上正式出版的書**：有排版節奏（章名頁、段落層次、圖說、引言框），
  **完整流暢的書寫文體**而非條列筆記。讓學員**會想珍藏**，不是「講義列印稿」。
- 淺色底（白／米白），橘紅系強調色
- 封面：大編號＋名稱＋副標＋三張資訊卡（**難度星等／要準備的／需要憑證**）
  - ⚠️ **不放「預估時間」**（每班程度不同）
- 頁首：單元編號＋名稱；頁尾：講師名 · 課程名＋頁碼；末頁：版權宣告
  （版權頁套 `aliang-author-info` skill）

## 七、⑥ 網站承載（**最容易被漏掉的一段**）

書做完只是半成品。學員打開資料夾看到 `P1_ebook.html`、`P2_ebook.html`……
**不知道要點哪個、不知道有幾本、不知道程式碼在哪**。要有一個入口。

### 架構（照 `F:\GAS\網站` 的樣態，已實測 32 項驗收全過）

```text
課程網站\
├── 啟動網站.bat        ← 雙擊就開（起本機伺服器＋開瀏覽器）
├── index.html          首頁：跑馬燈＋Hero＋卡片牆＋一覽表＋課前準備＋版權頁
├── reader.html         閱讀器（用 ?u=P1 決定載哪一本）
├── assets\
│   ├── style.css       首頁樣式
│   ├── reader.css      閱讀器樣式
│   └── reader.js       翻頁／目錄／縮放／整頁／雙頁／放大鏡／註記／程式碼面板
├── books\<單元>\      電子書 HTML ＋ 書中圖片
└── code\<單元>\       該單元的程式碼與素材（供下載）
```

**本包 `assets/site/` 已備妥全套可直接改的範本**，不用從零寫。

### 首頁要有的五塊

| 區塊 | 作用 |
|---|---|
| 跑馬燈 | 滾動公告，帶出各單元亮點 |
| Hero | 大標＋一句話講清楚這門課給什麼＋CTA |
| **卡片牆** | 一單元一張卡：編號／標題／一段介紹／頁數行數 → 點了進閱讀器 |
| 一覽表 | 條列快速跳轉（想直接找某一課的人用這個） |
| 課前準備 | **要學員先裝什麼**（耗時的安裝一定要寫「務必課前裝好」） |

卡片連結格式：`reader.html?u=P1`（沿用 GAS 的 `?u=U01` 作法）。

### 閱讀器一定要有的功能

| 分區 | 功能 |
|---|---|
| 導覽 | ☰目錄（列全書頁面可跳）、◀上一頁／下一頁▶、頁碼輸入、鍵盤 ← → |
| 檢視 | 🔍整頁縮放，點百分比回 100% |
| **檢視（2026-09 新增）** | ⛶**整頁顯示**（一整頁完整放進畫面，不用捲）／📖**雙頁跨頁**（左右兩頁＋書溝＋翻書動畫，翻頁一次跳兩頁）／🔎**區域放大鏡**（跟著滑鼠走的圓形鏡片，滾輪調鏡片大小、Shift+滾輪調倍率、Esc 關閉） |
| **註記** | ✏️畫畫 ↗️箭頭 ▭方框 ◯圓圈 🔤打字、粗細調整、↩復原(Ctrl+Z)、🗑️清除 |
| 資源 | 📋程式碼面板：多檔分頁、複製、下載 |

> **三個檢視功能的用途分工**（老師實際上課提出的需求）：
> 整頁縮放是改變版面；**放大鏡不改版面**，只放大鏡片底下那一塊，
> 適合上課指著截圖細節講解。雙頁跨頁像翻真書，適合展示前後對照的頁面。

**註記要逐頁分開存**（`notes[頁碼] = [圖形...]`），翻頁再翻回來筆記還在。
只存在記憶體、重新整理清掉是刻意的——教材保持乾淨，每次上課都是新的。

### 🔴 這段踩過的四個雷

1. **`hidden` 屬性會被 CSS `display:flex/grid` 蓋掉**
   → 看不見的面板仍然攔截點擊，**整排工具列按鈕按不動**。
   必修：`.toc-wrap[hidden],.sheet[hidden]{display:none!important}`
2. **不能直接雙擊 `index.html`**
   → 瀏覽器擋本機檔案讀取，`fetch` 程式碼會失敗、iframe 內容讀不到。
   **一定要附 `.bat` 起本機伺服器**，並在 README 和課堂上講清楚。
3. **書是 HTML 就用 iframe 承載，不要重寫**
   載入後 `doc.body.classList.remove('deck')`，改由外部控制 `.page` 的顯示，
   並隱藏書內自己的翻頁列。書和網站各自獨立，書單獨開也能看。
4. **註記 canvas 的座標要除以縮放倍率**
   `(e.clientX - rect.left) / zoom`，否則放大後畫的位置會跑掉。
5. **放大鏡的滑鼠事件不能掛在 `#book` 上**（2026-09 踩到）
   `#ink` 用 `position:absolute; inset:0` 蓋在 `#book` 上面，會把 mousemove 吃掉。
   **要掛在 `#stage`**，再用 `book.getBoundingClientRect()` 換算座標。
   另外 `#lens` 要寫 `inset:auto`，否則會被 `#ink` 那條 `inset:0` 波及而變形。
6. **`fitScale()` 預設是「填滿寬度」，看不到完整一頁**（老師實際反映）
   一定要另外做「整頁顯示」：`Math.min(依寬算, 依高算)`，
   並讓 `.stage` 在該模式下 `align-items:center; overflow:hidden`。
   雙頁時記得寬度要再除以 2（`cols = spread ? 2 : 1`）。

### 驗收（實跑，不是看程式碼）

起伺服器後用 Playwright 逐項點過：卡片可進書、翻頁／鍵盤／輸入頁碼、
目錄可跳、縮放、每種註記畫得出來、**翻頁後註記還在**、復原、
程式碼面板讀得到檔案且複製得到、手機版不溢出、Console 零錯誤。
**新增三項也要實測**：整頁顯示後書高 ≤ 畫面高且不用捲；
雙頁時右頁畫布真的有內容（取像素判斷，不能只看有沒有元素）、翻頁一次跳兩頁；
放大鏡鏡片會跟著滑鼠移動、鏡片內非白像素 > 0、滾輪能改大小與倍率。
