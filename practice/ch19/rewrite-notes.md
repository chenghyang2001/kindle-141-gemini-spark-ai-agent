# 重寫筆記：從 otto-skill 骨架學到什麼

> 參考對象：`Spark-skills/skills/01_start-here/otto-skill/SKILL.md`（控制 OTTO 機器人）與 `Spark-skills/README.md` 中的 SKILL.md 格式範例。
> 重寫成果：`ch19/course-book-tracker/SKILL.md`，內容是全新撰寫，沒有複製原文。

## 一、從骨架學到的三件事

1. **先分清楚「層次」，再決定怎麼做。**
   otto-skill 一開頭就用表格把工作分成「韌體工作流」和「即時遙控」兩種，告訴 AI 要先判斷使用者要哪一種。我在借閱表技能裡用了同樣的想法：先判斷是「寫入」還是「查詢」，寫入會改表格所以更小心，查詢只看不改。

2. **做不到的事要明講，不要假裝成功。**
   otto-skill 寫明沒有接上機器人時，只能做到編譯，不能假裝燒錄成功。這給我的啟發是：技能要寫出「做不到時怎麼回報」。所以我加了「找不到書名或借閱人就直接說，不要猜是哪一筆」。

3. **把不能碰的東西單獨列成「鐵律」。**
   otto-skill 有一段「重要規則」，列出函式庫不准改、固定的初始化寫法，讓 AI 一眼就知道紅線在哪。我把這個做法延伸成「權限邊界」，列出 5 條不准做的事。

## 二、跟原技能不同的兩個地方與理由

| # | 原技能（otto-skill） | 我的版本（course-book-tracker） | 理由 |
| --- | --- | --- | --- |
| 1 | description 主要是**功能描述＋觸發詞清單**（控制 OTTO、燒錄 OTTO、arduino-cli……） | description 用「**當我說『借出 某書 給 某人』『有哪些書逾期了』……時使用**」來寫 | 觸發詞清單只能比對關鍵字；寫成「當我說……時」，AI 更容易判斷像「黃品瑄還書了」這種沒有關鍵詞的句子也該啟用。這也是技能庫 README 特別強調的寫法 |
| 2 | 工作流程依賴**腳本與工具**（`otto_ctl.py`、`arduino-cli`、序列埠），而且是直接操作實體機器人 | 純文字規則，**不需要任何腳本**，只操作一份試算表；另外加上「驗收規則」與「權限邊界」兩段 | 班導不一定會裝工具或寫程式，純文字規則在 Spark、Claude 等任何支援技能的 AI 都能直接用。而借閱表會改到學生的紀錄、又可能想寄提醒給家長，所以要明確寫出「做完請我自己開檔確認」和「不准寄信、不准刪列」，這些在 otto-skill 裡沒有對應的段落 |
