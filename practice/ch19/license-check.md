# 授權確認：Spark-skills 技能庫

> 我實際讀了 `Spark-skills/LICENSE`（存在）與 `Spark-skills/README.md` 的「授權」段落。以下是用自己的話整理的理解，**不是法律意見**；真的要商用時，請以授權原文為準。

## 1. 這是什麼授權？

**MIT License（MIT 授權）**，著作權人是曾慶良（阿亮老師），年份 2026。MIT 是最寬鬆的開源授權之一。

## 2. 我可以做什麼？

幾乎什麼都可以：

- **使用**：直接拿技能檔去用。
- **修改**：改成自己的情境、自己的版本。
- **合併**：把它放進自己的專案或技能庫。
- **散布**：分享給同事、學生，或放到網路上。
- **再授權、販售**：包括商業用途，不用另外問作者、不用付費。

README 也用白話寫了同樣的意思：拿去用、改成你的，不用問作者。

## 3. 唯一的要求是什麼？

**保留授權聲明**：只要你散布的內容包含這個技能庫的全部或「實質部分」，就要附上原本的著作權聲明（Copyright (c) 2026 曾慶良）和 MIT 授權全文。

另外要知道一件事：授權寫明軟體是「**按現狀提供，不附任何保證**」，用了出問題，作者不負責。所以拿來用之前，還是要自己測試。

## 4. 如果我做成付費課程，要怎麼處理？

MIT 允許商業使用，所以**可以做成付費課程**。建議這樣處理：

| 情況 | 做法 |
| --- | --- |
| 課程中**直接發給學員**技能庫裡的 SKILL.md（原封不動或小幅修改） | 一起附上 `LICENSE` 檔（著作權聲明＋MIT 全文），例如放在講義附錄或檔案資料夾裡 |
| 只是**參考骨架、用自己的話完全重寫**（像本練習的 `course-book-tracker`） | 嚴格說不一定構成「實質部分」，但仍建議在課程資料註明「結構參考自 Spark-skills（MIT，曾慶良）」，這是業界的好習慣 |
| 簡報或影片中**展示**原技能的內容 | 在該頁或片尾標註來源與授權 |
| 不能做的事 | 不能把原作者的著作權聲明拿掉、改成自己的名字；也不要暗示原作者為你的課程背書 |

**還要注意一點：**技能庫的總授權是 MIT，但有些技能本身整併了其他來源，例如 `humanizer-zh-tw` 的 SKILL.md 裡列了好幾個 MIT 來源專案，`office` 註明所用工具是 Apache-2.0 授權。如果課程要用到這些技能，**要再看那個技能自己標示的來源與授權**，一併保留它們的聲明。
