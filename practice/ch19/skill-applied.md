## 一、套用了的規則

| SKILL.md 小節 | 套用的規則 | 在 `lend.gs` 裡怎麼做 |
| --- | --- | --- |
| 二、支援的運作模式 →「模式 A：僅生成程式碼」 | 預設只在本地產生程式碼，不連接或修改任何遠端專案 | 只寫成 `.gs` 檔，沒有執行、沒有登入 Google、沒有部署 |
| 二、支援的運作模式 →「權限與安全原則」 | 未經明確授權不修改試算表、不寄信；試算表內的功能不要部署成網頁應用程式 | 程式本身不寄信、不連外；檔頭寫明只需要 `spreadsheets.currentonly` 權限 |
| 三、作業步驟 SOP →「步驟 1：需求解析與權限評估」 | 先判斷需要哪些 Google 服務與權限範圍 | 判定只需要 `SpreadsheetApp`（加上 `LockService`、`Utilities`、`Session` 這些輔助服務），不需要 `MailApp`、`DriveApp`、`UrlFetchApp` |
| 步驟 2 → 1. 註解 | 註解一律用繁體中文台灣用語 | 每個函式與關鍵步驟都有繁中註解，說明「為什麼」 |
| 步驟 2 → 2. 模組化 | 功能拆成獨立函式，入口明確 | 入口是 `lendBook()` 與 `lendFromSentence()`；編號、日期格式、錯誤回報拆成 `nextId_`、`formatMonthDay_`、`fail_` |
| 步驟 2 → 3. 效能優化（批次處理） | 禁止在迴圈裡用 `getValue()`／`setValue()`，改用 `getValues()`／`setValues()` | 用 `getDataRange().getValues()` 一次讀整張表；新增的那一列用一次 `setValues()` 寫入 |
| 步驟 2 → 5. 併發與重複控制 | 寫入時加 `LockService.getScriptLock()` | 用 `tryLock(10000)` 避免兩人同時登記搶到同一個編號，並在 `finally` 釋放 |
| 步驟 2 → 6. 例外處理 | 核心流程包在 `try...catch`，用 `Logger.log()` 記錄 | 主流程包在 `try...catch...finally`；所有失敗都經過 `fail_()` 寫 Logger 並回傳 `ok:false` |
| 二點五 →「已內建的防護」第 6 點：缺欄位有預設值 | 缺資料時不要產生奇怪的結果 | 書名或借閱人空白時直接拒絕寫入；標題列缺欄位時也拒絕，並列出缺哪幾欄 |
| 二點五 →「已內建的防護」第 7 點：try/catch 包住主流程 | 錯誤要讓人看得到 | `lendBook()` 回傳清楚的 `message`，成功、失敗都能念給老師聽 |

## 二、沒有套用的規則與原因

| SKILL.md 小節 | 沒套用的規則 | 原因 |
| --- | --- | --- |
| 二、支援的運作模式 →「模式 B：生成並部署」 | 備份、驗證、用 clasp 推送到試算表 | 這次規定**不能執行程式**，也沒有取得部署授權，所以只走模式 A |
| 三、作業步驟 SOP →「步驟 3：部署與驗證（模式 B 專用）」 | 執行 `setup`／`backup`／`deploy` 腳本 | 同上，屬於模式 B |
| 二點五 → `homework-intake` 範本 | 「表單進、檔案歸、信件出」的範本優先取用 | 借閱登記沒有表單收檔、也不寄信，情境不同，硬套反而會多出寄信功能 |
| 二點五 → 防護第 2、4、7 點中跟寄信有關的部分（查配額、HTML／純文字雙版本、失敗寄信通知老師） | 寄信相關防護 | 任務明確規定**不得寄信**；錯誤改用 Logger 與回傳訊息讓老師知道 |
| 二點五 → 防護第 3 點 `esc()` 跳脫 | 防止 HTML 破版 | 這支程式沒有產生 HTML（沒有信件、沒有側邊欄），資料只寫進儲存格 |
| 二點六、寄信的正確做法 | MailApp／GmailApp 用法與配額 | 不寄信，不適用 |
| 步驟 1 → 寫入 `appsscript.json` 的 `oauthScopes` | 產出清單檔 | 任務只要求 `lend.gs`；所需權限範圍改寫在檔頭註解，實際建立專案時再補上 |
| 步驟 2 → 4. 安全配置（`PropertiesService`） | 不硬編碼 API Key | 這支程式沒有任何金鑰或密碼；分頁名稱與借期放在 `LEND_CONFIG` 方便修改 |

## 三、技能沒寫、我自己補的

- **日期欄位先設成純文字再寫入**（`setNumberFormat('@')`）：任務要求日期用「月-日」文字，不先設格式的話，試算表會把 11-15 自動轉成日期。
- **編號用「最大值＋1」而不是列數**：中間有人刪過列時，用列數會產生重複編號。
- **依實際標題順序寫入**：欄位被調換順序也不會寫錯欄。

## 四、驗證方式

程式**沒有在 Google Apps Script 執行**。我只在本機做了檢查（不連 Google、不寄信）：

1. `node --check` 語法檢查通過。
2. 用假的試算表模擬執行：
   - 「借出 想飛的鋼琴少年 給 黃品瑄」→ 新增 B06，寫在第 7 列，既有 B01～B05 沒有變動，寫入前有先設成純文字。
   - 書名空白 → 拒絕寫入，回傳「書名是空白的」。
   - 找不到「借閱紀錄」分頁 → 拒絕寫入，回傳找不到工作表。
   - 12-25 借出 → 應還日正確跨年為 01-08。
