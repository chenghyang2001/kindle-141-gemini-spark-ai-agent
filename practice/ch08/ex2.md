# 練習 2：用 meeting-notes-organizer 整理會議記錄

> 技能：`.claude/skills/meeting-notes-organizer/SKILL.md`（v1.0.0，10 條規則）。會議記錄為虛構範例。

## 原始記錄

> 週五小組會議。大家同意下週一開始試跑新流程。小美說她可以負責整理使用手冊，這個月底前交。阿宏說要找廠商報價，但沒講什麼時候。還有一個問題，是不是要多買兩台平板，大家意見不一，沒有結論。

---

## 整理結果（技能輸出）

## 一、會議決議
- 下週一開始試跑新流程

## 二、待辦事項
| # | 事項 | 負責人 | 期限 |
| - | ---- | ------ | ---- |
| 1 | 整理使用手冊 | 小美 | 這個月底前 |
| 2 | 找廠商報價 | 阿宏 | 待確認 |

## 三、需要後續討論
- 是否多買兩台平板（意見不一，無結論）

---

## 規則檢查

| # | 規則 | 遵守 | 說明 |
| - | ---- | ---- | ---- |
| 1 | 只整理成三段 | ✅ | 只有決議／待辦／後續討論，無其他段落 |
| 2 | 待辦要有負責人與期限兩欄 | ✅ | 兩項都有兩欄 |
| 3 | 🔴 沒負責人或期限 → 待確認，不推測 | ✅ | 阿宏「沒講什麼時候」→ 期限填「待確認」，未編成「下週」之類 |
| 4 | 語氣簡潔、一項一行 | ✅ | 全是短句 |
| 5 | 不加評論 | ✅ | 無建議、無總結感想 |
| 6 | 忠於原文 | ✅ | 未補廠商名、平板型號、預算 |
| 7 | 未定案放第三段 | ✅ | 平板「沒有結論」→ 第三段，未放決議 |
| 8 | 相對日期照原文 | ✅ | 「下週一」「這個月底前」都沒換算成具體日期 |
| 9 | 沒內容寫「（無）」 | ✅（不適用） | 三段都有內容 |
| 10 | 繁中、人名照原文 | ✅ | 小美、阿宏照原文 |

**「待確認」規則細看**

- 阿宏的報價期限 → 「待確認」✅（最容易被 AI 自作主張補日期的地方）
- 小美的期限有寫（這個月底前）→ 照填，不標待確認 ✅
- 「試跑新流程」是決議不是待辦，沒有硬拆成待辦再補負責人 ✅
- 可改進：「這個月底前」幾個月後再看會不知道是哪個月，可在 SKILL.md 加一條「若記錄有會議日期，寫在標題」。

## 搬到別台電腦／別的 AI 怎麼用

| 情境 | 做法 | 要改嗎 |
| ---- | ---- | ------ |
| 另一台電腦的 Claude Code（整個 practice 資料夾複製） | 在該資料夾開 `claude`，`.claude/skills/` 是專案層技能，自動載入 | 不用改 |
| 想在所有專案都用 | 把 `meeting-notes-organizer/` 複製到 `~/.claude/skills/` | 不用改 |
| 其他支援 Agent Skills 格式的 AI | 把技能資料夾放到該平台的技能目錄或上傳 zip | 大多不用改，見下 |

**可能要檢查的地方**

- 資料夾名稱必須等於 `name`（`meeting-notes-organizer`）——目前一致。
- `version`／`source` 不是標準欄位：Claude Code 會忽略；較嚴格的平台可能警告，可移到 `metadata:` 底下。
- `description` 長度上限約 1024 字元——目前沒超過。
- 若對方平台用英文判斷觸發，可在 description 補 `meeting notes`、`minutes`。
- 技能本身只做文字整理、不呼叫工具，所以沒有連接器或權限要搬。
