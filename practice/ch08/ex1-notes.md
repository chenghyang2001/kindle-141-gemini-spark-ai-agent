## 二、我補充的部分

| 補充內容 | 為什麼要補 |
| --- | --- |
| **description 的使用時機與 7 種常見說法** | Gem 是使用者自己點進去才用；技能要靠說明欄讓 Spark 自己判斷什麼時候啟用，所以要寫出使用者真的會說的話 |
| **名稱 `meeting-notes-organizer`** | 技能需要一個小寫英文加連字號的代號，原提示詞沒有 |
| 規則 3 補「也不要從職稱或上下文推測」 | 原本只寫「不要自己編」，但「推測」是最容易發生的編造方式，所以講明 |
| 規則 4「只用記錄裡的內容」 | 原提示詞只限制負責人與期限不能編，沒有限制其他內容；補上避免加入外部資訊 |
| 規則 6「歸類原則」 | 原提示詞沒說怎麼判斷一句話該放哪一段，補上讓結果穩定 |
| 規則 7「某段沒有內容時寫（本次會議無）」 | 避免缺段落時，使用者以為漏整理 |

| 注意事項：不寄信、不修改原始記錄 | 技能可能被自動啟用，要明確寫出權限邊界 |
