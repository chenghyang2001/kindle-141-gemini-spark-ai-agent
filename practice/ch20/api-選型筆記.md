# API 選型筆記（草稿，未實際呼叫）

> 這份筆記是**草稿**：沒有連網、沒有執行任何程式。API 名稱來自我的既有知識，**不附網址**；使用前請自行到官方文件確認現況（是否仍免金鑰、使用限制、授權條款）。

## 三個虛構情境

| 代號 | 情境 |
| --- | --- |
| **情境 A** | 週末要帶班上去河濱公園寫生，想知道週六、週日會不會下雨，要不要提醒學生帶傘。 |
| **情境 B** | 班級書櫃收到一批捐贈的書，想用書背上的 ISBN 查出版社與出版年，補進借閱表。 |
| **情境 C** | 班上要做隨機抽籤，想幫每位學生（用座號代表）產生一個卡通頭像，避免使用學生真實照片。 |

## 一、5 種不需要申請金鑰的免費公開 API

| # | API 名稱 | 用途 | 適合的情境 | 可信度 |
| --- | --- | --- | --- | --- |
| 1 | **Open-Meteo**（天氣預報） | 依經緯度查未來幾天的氣溫、降雨機率、降雨量 | **情境 A** | 我知道它以免金鑰聞名；商業用途條件**需自行查證** |
| 2 | **Open Library**（開放圖書資料） | 依 ISBN 或書名查書籍的出版社、出版年、作者 | **情境 B** | 免金鑰；但中文書的收錄是否完整**需自行查證** |
| 3 | **DiceBear**（頭像產生） | 輸入一段文字當「種子」，產生固定的卡通頭像圖片 | **情境 C** | 免金鑰；各頭像風格的授權不同，**需自行查證** |
| 4 | **Frankfurter**（匯率） | 查各國貨幣的每日參考匯率 | 三個情境都不適用（備用，例如校外教學經費換算） | **需自行查證**是否仍在維護 |
| 5 | **Wikipedia REST API**（維基百科摘要） | 依條目名稱取得簡短摘要 | 情境 B 的延伸（查作者簡介）；不是主要資料來源 | 免金鑰，但官方建議設定可辨識的 User-Agent，**需自行查證**細節 |

> 沒有選的：中央氣象署開放資料最符合台灣天氣，但**需要申請授權碼**，不符合「不需要金鑰」的條件，所以沒有列入。

## 二、給 AI 的寫程式指令草稿

### 情境 A：週末要不要帶傘

> 請幫我寫一段 Google Apps Script（函式名稱 `checkWeekendRain`），查詢週末的降雨機率，判斷要不要提醒學生帶傘。
>
> **1. 資料在哪**
>
> - 使用 Open-Meteo 的天氣預報 API（不需要金鑰）。網址與參數名稱請以 Open-Meteo 官方文件為準，不要自己猜。
> - 地點用經緯度，寫成程式最上方的常數 `LAT`、`LON`，我會自己填河濱公園的座標。
> - 只需要「每日最高降雨機率」與「每日降雨量」兩項。
>
> **2. 回傳長什麼樣**（以下是我自擬的範例，實際欄位名稱請對照官方文件）
>
> ```json
> {
>   "daily": {
>     "time": ["2026-11-21", "2026-11-22"],
>     "precipitation_probability_max": [70, 20],
>     "precipitation_sum": [5.2, 0.0]
>   }
> }
> ```
>
> **3. 缺資料怎麼辦**
>
> - 某一天的降雨機率或降雨量沒有值時，該欄顯示「未提供」，**不可出現 undefined、null 或 NaN**。
> - 整個 API 連不上或回傳不是 200 時，回報「查詢失敗：天氣資料未提供」，不要用猜的數字。
>
> **4. 格式限制**
>
> - 輸出成一張表：日期、降雨機率、降雨量、建議（機率 ≥ 50% 寫「帶傘」，否則寫「不用帶」）。
> - 不放任何金鑰；不加我沒要求的功能（不寄信、不寫入試算表、不建立觸發器）。
> - 程式加繁體中文註解。

### 情境 B：查書的出版社資料

> 請幫我寫一段 Google Apps Script（函式名稱 `lookupBookByIsbn`），輸入一個 ISBN，查出這本書的書名、出版社、出版年。
>
> **1. 資料在哪**
>
> - 使用 Open Library 的書籍資料 API，以 ISBN 查詢（不需要金鑰）。網址格式請以 Open Library 官方文件為準。
> - ISBN 由我傳入，先去掉中間的連字號與空白再查詢。
>
> **2. 回傳長什麼樣**（以下是我自擬的範例，實際欄位名稱請對照官方文件）
>
> ```json
> {
>   "title": "想飛的鋼琴少年",
>   "publishers": ["某某出版社"],
>   "publish_date": "2020"
> }
> ```
>
> **3. 缺資料怎麼辦**
>
> - 書名、出版社、出版年任何一項沒有，該欄顯示「未提供」，**不可出現 undefined**，也不可用其他欄位的資料去補。
> - 出版社有多個時，用「、」連接。
> - 查不到這本書（例如回傳 404）時，回報「查無此 ISBN：資料未提供」，不要自己編書名或出版社。
>
> **4. 格式限制**
>
> - 只回傳一個物件：`{ isbn, title, publisher, publishYear }`，不自動寫入借閱表。
> - 不放金鑰；不加我沒要求的功能（不抓封面圖、不查作者簡介）。
> - 程式加繁體中文註解。

### 情境 C：隨機抽籤用的卡通頭像

> 請幫我寫一段網頁用的 JavaScript（函式名稱 `buildAvatarList`），輸入座號清單，為每個座號產生一個卡通頭像的圖片網址，並隨機抽出一位。
>
> **1. 資料在哪**
>
> - 使用 DiceBear 的頭像 API（不需要金鑰），用「座號」當種子，同一個座號每次都會得到同一張頭像。網址格式與可用風格請以 DiceBear 官方文件為準。
> - **只傳座號，不傳學生姓名**，避免把個資送到外部服務。
>
> **2. 回傳長什麼樣**（DiceBear 回傳的是圖片；以下是我希望函式整理出來的資料，自擬範例）
>
> ```json
> {
>   "avatars": [
>     { "seat": "01", "imageUrl": "（依官方格式組成的圖片網址）" },
>     { "seat": "02", "imageUrl": "（依官方格式組成的圖片網址）" }
>   ],
>   "picked": "02"
> }
> ```
>
> **3. 缺資料怎麼辦**
>
> - 座號清單是空的，回報「沒有座號資料，未提供頭像」，不要產生空白清單假裝成功。
> - 某個座號是空白或不是數字，該筆 `imageUrl` 寫「未提供」，**不可出現 undefined**，並在畫面上提示是哪一筆。
> - 圖片載入失敗時，顯示座號文字代替，不顯示破圖。
>
> **4. 格式限制**
>
> - 座號一律補成兩位數（1 → 01）。
> - 不放金鑰；不加我沒要求的功能（不儲存結果、不上傳、不記錄誰被抽中）。
> - 程式加繁體中文註解。

## 三、這份草稿我沒有實際呼叫過

我**沒有連網、也沒有執行任何程式**，以下細節都需要人工到官方文件驗證：

| 項目 | 需要驗證的細節 |
| --- | --- |
| **網址** | 三個 API 的實際網址與路徑，我刻意沒寫，請從官方文件複製 |
| **欄位名稱** | 情境 A 的 `precipitation_probability_max`、`precipitation_sum`；情境 B 的 `title`、`publishers`、`publish_date`，都是我依印象自擬的，實際名稱與結構可能不同（例如 Open Library 不同查詢方式回傳的格式不一樣） |
| **參數** | 天氣 API 需要哪些參數（時區、預報天數）、DiceBear 的版本號與頭像風格名稱 |
| **是否仍免金鑰** | 免費 API 的政策會變動，使用前確認現在是否仍不需要金鑰 |
| **使用限制** | 每日或每分鐘的呼叫次數上限、是否允許商業用途、頭像圖片的授權 |
| **資料覆蓋率** | Open Library 對中文書（尤其台灣出版品）的收錄可能不完整，查不到的比例需實測 |
| **時區與日期** | 天氣資料的日期是否以台灣時間計算，需實測確認 |

建議驗證順序：先在瀏覽器手動打開官方文件提供的範例網址，看實際回傳的 JSON，再把真實欄位名稱交給 AI 改寫程式。
