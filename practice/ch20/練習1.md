## 三個虛構情境

- **A**：週末去河濱公園寫生，要不要提醒學生帶傘。
- **B**：用捐贈書的 ISBN 查出版社與出版年，補進借閱表。
- **C**：隨機抽籤時，用座號產生卡通頭像（不用學生照片）。

## 1. 5 種不需要金鑰的免費 API（只寫名稱，不附網址）

| API | 用途 | 適合情境 |
| --- | --- | --- |
| Open-Meteo | 天氣預報（降雨機率、降雨量） | A |
| Open Library | 依 ISBN 查書籍資料 | B |
| DiceBear | 用文字種子產生卡通頭像 | C |
| Frankfurter | 每日匯率 | 都不適用（備用） |
| Wikipedia REST API | 條目摘要 | B 的延伸 |

使用限制、是否仍免金鑰、中文書收錄率、頭像授權等都標「需自行查證」。中央氣象署資料需要授權碼，所以沒列入。

## 2. 三段寫程式指令草稿

每段都包含四件事：

- **資料在哪**：指定 API，網址請 AI 以官方文件為準、不要猜；情境 C 只傳座號、不傳姓名。
- **回傳長什麼樣**：各附一段自擬 JSON 範例，並註明欄位要對照官方文件。
- **缺資料怎麼辦**：一律顯示「未提供」，不可出現 undefined；連線失敗或查無資料時明確回報，不編造。
- **格式限制**：不放金鑰；不加沒要求的功能（不寄信、不寫入試算表、不儲存或上傳）。

## 3. 這份草稿我沒有實際呼叫過

需要人工驗證：三個 API 的實際網址、JSON 欄位名稱（例如降雨機率與出版社欄位都是我自擬的）、參數與版本、是否仍免金鑰、呼叫次數與商用限制、中文書收錄率、天氣日期的時區。建議先手動打開官方範例看真實回傳，再讓 AI 改寫。
