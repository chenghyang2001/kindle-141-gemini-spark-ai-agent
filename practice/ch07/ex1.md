```markdown
# 讀書會簽到登記

## 使用說明

1. **資料放哪**：簽到紀錄一律寫進試算表「讀書會簽到紀錄」的「簽到」分頁；彙整結果放在同一份試算表的「月統計」分頁，不另外建新檔。
2. **只讀不改**：「成員名單」分頁只讀不改。登記的姓名必須是名單上的人；名單上找不到的姓名，不要自動新增，標成【待確認】並問使用者。
3. **欄位順序**：「簽到」分頁固定為「日期、姓名、狀態、備註」四欄，順序不可調換，也不可新增欄位。
4. **日期格式**：一律寫成 `YYYY-MM-DD`（例如 2026-11-19）。使用者說「今天」「這週四」時，換算成實際日期再寫入；換算不出來就標【待確認】。
5. **可接受的類別**：「狀態」只能是「出席」「請假」「遲到」三種。遲到的分鐘數或請假原因寫在「備註」；使用者說「缺席」「沒來」但沒說原因時，先問是請假還是未到，不要自己猜。
6. **不重複登記**：同一個人同一天只能有一列。已經有紀錄時，列出「原本 → 新的」讓使用者確認後才修改，不直接覆蓋。
7. **彙整方式**：使用者要統計時，依「月份 × 姓名」計算出席、請假、遲到的次數，並算出席率（出席＋遲到）÷ 聚會次數；只統計表格裡已有的紀錄，不補推沒登記的日期。
8. **完成後回報**：用一句話回報「已登記 N 筆：誰、哪天、什麼狀態」，最後附上目前「簽到」分頁的總列數。**不寄信、不發訊息通知任何成員**，也不在群組貼出缺席名單。
```

## 為什麼名稱不用中文、說明不寫成功能簡介

**名稱用全小寫英文加連字號**（`book-club-checkin`），是因為技能名稱通常會變成資料夾名稱和系統內部代號。英文小寫加連字號在各種平台、檔案系統和網址都不會出現編碼或大小寫問題，也比較容易打字和搜尋；中文名稱放在內文標題就好。

**說明不寫成功能簡介**，是因為說明欄的真正用途是讓代理人判斷「**現在該不該啟用這個技能**」。如果只寫「這是一個簽到工具」，代理人聽到「小美今天請假」時，很可能認不出這句話跟簽到有關。所以說明要寫清楚使用時機，並列出使用者平常真的會說的話：口語的「點名」、簡短的「幫我簽到」、同義的「沒來」「缺席」。這樣不管怎麼說，代理人都能接得上。
