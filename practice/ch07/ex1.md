```markdown
# 讀書會簽到登記

每週一次的讀書會，記錄每位成員的出席、請假、遲到，並能彙整出缺席統計。

## 規則

1. **資料位置**：簽到資料只存在 `ch07/checkin.csv`（UTF-8、含標題列）。檔案不存在時才建立，並先寫入標題列。
2. **只讀不改**：既有的歷史紀錄一律只讀，不修改、不刪除；登記只能「附加新的一列」。若使用者要更正，先列出原紀錄，再附加一筆「備註：更正」的新紀錄，不覆寫舊列。
3. **欄位順序固定**：`日期,姓名,類別,備註`，不可增減或調換欄位；備註可留空，含逗號時以雙引號包住。
4. **日期格式**：一律 `YYYY-MM-DD`（例：2026-11-17）。使用者說「今天」「上週三」時，先換算成實際日期再寫入，並在回報中寫出換算結果。
5. **可接受的類別**：只接受「出席」「請假」「遲到」三種。口語同義詞先對應（有來／到了→出席；不能來／缺席報備→請假；晚到→遲到），無法對應的不寫入，並說明原因。
6. **避免重複**：同一日期同一姓名已有紀錄時不再新增，改為回報已存在的那一列。
7. **彙整方式**：統計時依姓名分組，計算出席、請假、遲到次數與出席率（出席＋遲到 ÷ 總場次），用 Markdown 表格呈現，依出席率由高到低排序；可依日期區間（某週、某月）篩選。
8. **完成回報**：回報新增或查到的列（原樣顯示）、目前總筆數與檔案路徑。只在終端機回報，**不寄信**、不建草稿、不傳任何訊息給成員。
```

## 為什麼 name 不用中文、description 不寫成功能簡介

- **name 是識別碼，不是標題**：它同時是資料夾名稱和斜線指令（`/book-club-checkin`）。全小寫英文加連字號在各系統的檔案路徑、命令列輸入都不會出錯；中文名稱在終端機輸入、路徑編碼（cp950／UTF-8）、跨機器同步時容易出問題，也不符合技能規格。
- **description 是「觸發條件」，不是介紹文**：Claude 只看 description 來決定這次要不要載入技能。寫成「本技能可管理讀書會出缺席」這種功能簡介，模型很難把使用者的口語（「阿明遲到了」「誰缺席最多」）對上它，容易該觸發卻沒觸發。列出實際會講的說法、同義詞，再加一句「不觸發」的情境，才能讓它準確啟用、也不亂啟用。
