# 排程設計單：課程練習_每日報名摘要（Claude Code routine 版）

> 情境虛構：某社團的活動報名紀錄。資料在本機 `ch06/signup-records.csv`，雲端版為 Google 試算表「課程練習_活動報名紀錄」（資料夾「K141-課程練習」）。
> 排程由控制台建立，本單只負責設計。

## 1. 基本資料

| 項目 | 內容 |
| --- | --- |
| 排程名稱 | **課程練習_每日報名摘要** |
| 執行時間 | **每天 07:00（台北時間，UTC+8）**；cron 為 `0 7 * * *`（時區 Asia/Taipei），若平台只吃 UTC 則寫 `0 23 * * *` |
| 需要的連接器 | Google 雲端硬碟（只用搜尋、讀取、建立／更新一份文件） |

## 2. Routine 提示詞（七欄位，可直接貼進 routine）

```text
【目標】
每天早上統計社團活動報名狀況，產出三個數字：新增報名人數、已繳費人數、待跟進人數，讓幹部一眼看懂。

【資料來源】
只讀 Google 雲端硬碟資料夾「K141-課程練習」裡的試算表「課程練習_活動報名紀錄」，
欄位：日期、姓名、是否繳費、是否待跟進。不讀其他檔案、不讀信件、不上網。

【執行步驟】
1. 在資料夾「K141-課程練習」搜尋標題完全等於「課程練習_活動報名紀錄」的試算表，讀取全部列。
2. 新增報名人數 = 「日期」等於執行日前一天（台北時間）的列數。
3. 已繳費人數 = 「是否繳費」為「是」的列數（全部累計）。
4. 待跟進人數 = 「是否待跟進」為「是」的列數，並列出姓名。
5. 在同一資料夾搜尋 Google 文件「課程練習_每日摘要」：
   - 不存在 → 建立這份文件（只建一次）。
   - 已存在 → 用今天的結果覆寫整份內容。
6. 文件最後一行寫：「更新時間：YYYY-MM-DD HH:MM（台北時間）」。

【判斷規則】
- 只依表格資料計算，不推測、不補資料。
- 「是否繳費」「是否待跟進」不是「是／否」的列，計入「資料異常」並寫出列號。
- 找不到來源試算表、讀取失敗、或搜到多份同名「課程練習_每日摘要」時：不寫數字、不新建文件，
  只在既有那份摘要（若唯一存在）寫「執行失敗：原因」＋更新時間；否則就結束並回報失敗原因。

【輸出位置與格式】
固定一份 Google 文件「課程練習_每日摘要」，放在資料夾「K141-課程練習」。
內容格式：
  課程練習_每日摘要
  資料來源：課程練習_活動報名紀錄（共 N 筆）
  - 新增報名（昨日）：X 人
  - 已繳費：Y 人
  - 待跟進：Z 人（姓名…）
  - 資料異常：0 筆
  更新時間：YYYY-MM-DD HH:MM（台北時間）

【時間或觸發】
每天 07:00（台北時間）執行一次；不因資料變動觸發，也不在其他時間自行重跑。

【權限邊界】
- 來源試算表只讀：不修改、不排序、不加欄、不刪列。
- 不寄信、不建草稿、不發任何通知；不分享任何檔案、不改權限。
- 只能建立或覆寫「課程練習_每日摘要」這一份文件；不動資料夾內外的任何其他檔案。
```

### 輸出示意（2026-11-18 07:00 執行）

```text
資料來源：課程練習_活動報名紀錄（共 6 筆）
- 新增報名（昨日）：2 人
- 已繳費：3 人
- 待跟進：2 人（李美君、林佳慧）
- 資料異常：0 筆
更新時間：2026-11-18 07:00（台北時間）
```

## 3. 三原則對照

| 提示詞內容 | 落實的原則 |
| --- | --- |
| 只讀「課程練習_活動報名紀錄」四欄，不讀信、不上網 | 能唯讀就唯讀 |
| 來源試算表不修改、不排序、不加欄、不刪列 | 能唯讀就唯讀 |
| 不寄信、不建草稿、不分享、不改權限 | 能唯讀就唯讀 |
| 只能建立／覆寫「課程練習_每日摘要」一份文件 | 能唯讀就唯讀（寫入範圍縮到最小） |
| 固定一份文件、放「K141-課程練習」，不存在才建、存在就覆寫 | 產出放固定位置 |
| 搜到多份同名摘要就不新建、改回報失敗 | 產出放固定位置（防止越跑越多份） |
| 最後一行寫「更新時間」 | 要留時間戳 |
| 失敗時也寫「執行失敗：原因」＋更新時間 | 要留時間戳（看得出是今天壞掉，不是昨天的舊數字） |

## 4. 怎麼關掉

**停用（可隨時恢復）**
1. 開 claude.ai/code 的 Routines 頁（或在 Claude Code 輸入 `/schedule` 列出排程）。
2. 找到「課程練習_每日報名摘要」，把開關切成停用。
3. 隔天 07:00 後看「課程練習_每日摘要」的更新時間，確認**沒有**變動。

**刪除（無法復原）**
1. 先停用並觀察一天。
2. 在同一頁選該 routine → 刪除 → 確認名稱無誤再按確認。
3. 刪 routine 不會刪雲端檔；摘要文件與試算表依 `cleanup.md` 另行清理。

**什麼情況該停用**
- 活動截止報名，不再需要每日統計。
- 來源試算表改名、換欄位或搬資料夾（可能讀錯或讀不到）。
- 摘要「更新時間」沒更新，或連續兩天「執行失敗／資料異常」。
- 摘要數字和手算不一致；或資料夾出現多份「課程練習_每日摘要」。
- 發現它做了權限邊界外的事（寄信、分享、改來源）→ 立刻停用再查。
