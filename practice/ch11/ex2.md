## 二、排程設計單：每月報帳檢查

- **排程名稱**：練習_每月報帳檢查
- **執行時間**：每月 **28 日 09:00**（台北時間，UTC+8）
  - 選 28 日是因為每個月都有 28 日（2 月也有），而且離月底還有幾天，可以補齊單據。

### 使用說明（七欄位）

| 欄位 | 內容 |
| --- | --- |
| **目標** | 每月提醒並檢查當月報帳：統計各類別筆數與金額，列出還沒處理完的項目，讓我在月底前補齊。 |
| **資料來源** | 只讀取試算表「練習_報帳明細」中，日期屬於當月的列（欄位：編號、日期、店家、品項、金額、發票號碼、狀態）；不讀信件、不讀其他檔案、不上網。 |
| **執行步驟** | (1) 篩選當月的列 (2) 依類別計算筆數與金額小計 (3) 計算合計並驗算 (4) 列出所有留白欄位或狀態為「待確認」的項目 (5) 寫成月報檔 |
| **判斷規則** | 只依表格資料計算，不補資料、不猜留白的欄位；金額欄是空白或不是數字的列，不算進小計，改列入待處理清單；當月沒有任何資料時，月報寫「本月無報帳資料」，不產出 0 元報表冒充正常。 |
| **輸出位置與格式** | 固定存到 Google Drive「`練習_報帳月報/`」資料夾；檔名 `報帳月報_YYYY-MM_執行於YYYYMMDD-HHMM.md`；每次一個新檔、不覆蓋舊檔；第一行寫「執行時間」與「資料讀取時間」。 |
| **時間或觸發** | 每月 28 日 09:00 自動執行一次；不因資料變動而觸發。 |
| **權限邊界** | 報帳明細表**唯讀**，不修改、不排序、不刪除任何列，也不自動補欄位；**不寄信**、不發訊息、不送出任何報帳申請；只能在「練習_報帳月報/」資料夾新增檔案。 |

### 驗收後要暫停

1. 第一次執行後（或手動「立即執行」一次後），到「練習_報帳月報/」確認：
   - 有產生一個新檔，檔名與第一行都有時間戳。
   - 類別小計與合計跟自己手算的一致。
   - 待處理清單有列出 F2、F3。
   - 報帳明細表內容沒有被改動，寄件備份裡沒有任何新信件。
2. **驗收完成後，到排程清單把「練習_每月報帳檢查」設為暫停。**這是練習用的排程，暫停後確認下個月 28 日沒有再產生新檔；要正式使用時，再另外建立不帶「練習_」的正式排程。

## 三、技能設計：expense-helper

```markdown
---
name: expense-helper
description: 協助個人報帳：讀取發票或收據內容登記成報帳明細，月底依類別統計筆數與金額，並列出還沒處理完的項目。看不清楚的字一律留白，不猜。使用時機：(1) 使用者給發票、收據的照片或文字要登記報帳，(2) 使用者要看這個月花了多少、各類別多少，(3) 使用者要知道還有哪些單據沒處理完。常見說法：「幫我登記這張發票」「這幾張收據幫我報帳」「這個月報帳多少錢」「月底報帳整理一下」「還有哪幾張沒弄好」「幫我算一下交通費」「發票拍好了，幫我記」。關鍵詞：報帳、發票、收據、單據、費用、核銷、月報、小計。
---

# 報帳小幫手

## 使用說明

1. **資料位置**：報帳明細一律寫在試算表「報帳明細」，欄位固定為「編號、日期、店家、品項、金額、發票號碼、狀態」，不新增欄位、不改順序。
2. **留白而不是猜**：發票上讀不出來的字就留白，並告訴使用者是哪一張、哪一欄；看得到幾個字就只寫幾個字，不依常理補完。
3. **不編造**：絕對不編造店家、品項、金額、發票號碼；類別如果發票上沒寫，可以依品項判斷，但要標明「類別為 Spark 判斷」。
4. **狀態規則**：完全清楚的寫「草稿」；有任何留白的寫「待確認」並附原因；只有使用者確認後才能改成「已確認」。
5. **統計方式**：依類別計算筆數與金額小計，再算合計，並列出驗算過程；金額不是數字的列不算進小計，改列入待處理清單。
6. **只存草稿、不寄信**：所有報帳資料只存成草稿，不寄信、不發訊息，也不送出任何報帳申請。
7. **固定回報**：每次動作後回報寫入筆數、待確認筆數、本月合計，以及「未寄信、未送出」。
```

## 四、真實使用前一定要手動核對的 2 個欄位

### 1. 金額

金額是報帳最直接的結果，錯一個數字就是實際的錢對不上。照片辨識很容易把 1 和 7、0 和 8、逗號和小數點看錯，例如 1,345 被讀成 1.345，或 135 被讀成 185。**最危險的是，這些錯誤讀出來的結果都是「看起來正常」的數字**，不會被標成待確認，所以一定要拿發票原件逐張對照。

### 2. 發票號碼

發票號碼是查帳、防止重複報帳的依據。號碼只要錯一碼，就可能變成另一張發票，或讓同一張發票被報兩次也比對不出來。跟金額一樣，號碼讀錯時格式還是正確的（兩個英文字母加八位數字），**不會觸發留白規則**，系統也看不出有問題，只能靠人工對照原件。

> 為什麼不是挑店家或品項？因為那兩欄這次已經被留白、列進待處理清單，你一定會去看。真正需要防範的，反而是**已經填好、看起來很有把握**的欄位；金額和發票號碼一旦讀錯，不會有任何警示。
